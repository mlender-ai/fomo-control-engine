# PNF 측정 목표 (Law of Cause and Effect)

WO-FCE-PNF-TARGET-01 정본.

> **이것은 진입 시그널이 아니라 목표 계산기다.**
> PNF는 새 감지기가 아니다. 이미 `structure/wyckoff/engine.py`가 식별한 축적/분산 구간(Trading
> Range)에 대해 "누적된 원인의 크기"를 목표 가격으로 환산할 뿐이며, **진입 판단 로직에는 어떤
> 새 시그널도 추가하지 않는다.** 신규 감지기 모라토리엄(AGENTS.md)의 대상이 아닌 이유다.

## 왜 필요했나 — RR 게이트 기아

기존 RR의 보상 분자는 `take_profit[0]`, 즉 **가장 가까운 목표 하나뿐**이었다.

```python
reward = float(targets[0]["distance_pct"])   # 수리 전
rr = reward / risk
```

실제 운용은 TP1/TP2/TP3 분할 청산인데 RR은 TP1만으로 계산되므로 보상이 **체계적으로 과소평가**된다. 구조 레벨이 촘촘한 종목에서는 첫 목표가 손절폭보다 가까워 RR<1이 항상 발생한다. 실측에서 US 거부 사유 중 `risk_reward`가 22건, NVDA는 RR 0.53 / 임계 1.5였다.

즉 **RR 게이트가 종목을 거르는 게 아니라 목표 산출 방식이 스스로를 거르고 있었다.**

와이코프 3원칙 중 엔진은 Effort vs Result(볼륨)와 Supply & Demand(구조)는 다뤘지만 **Law of Cause and Effect**(축적 폭 → 목표 크기)를 목표 산출에 반영하지 않았다. PNF 수평 카운트가 정확히 그 빈자리다.

## 수평 카운트 원리

```
측정 목표 = 카운트 라인 + (축적 구간 열 수 × 박스 크기 × 리버설)
```

- **카운트 라인**: 축적 구간의 하단(지지). 고전적 방식을 따른다.
- **열 수**: TR 대역과 겹치는 PNF 열만 센다. 구간 밖 추세 구간의 열은 축적(Cause)이 아니다.
- Cause(횡보하며 쌓인 물량)가 클수록 Effect(이후 이동 폭)가 크다는 와이코프 명제의 정량화다.

## 박스 크기 산출 규칙 (고정)

```
box = clamp(ATR × 0.5,  price × 0.005,  price × 0.03)
```

ATR이 없거나 0이면 `price × 0.01`로 폴백한다.

| 상수 | 값 | 근거 |
|---|---|---|
| `BOX_ATR_FRACTION` | 0.5 | ATR 절반을 1박스로 — 같은 3% 박스도 저변동 종목엔 과도하게 촘촘하고 고변동 종목엔 성기다 |
| `MIN_BOX_PCT` | 0.005 | 하한. 박스가 너무 작으면 열이 수백 개로 흩어져 카운트가 무의미해진다 |
| `MAX_BOX_PCT` | 0.03 | 상한. 박스가 너무 크면 열이 1~2개로 뭉쳐 원인 축적을 못 센다 |
| `DEFAULT_BOX_PCT` | 0.01 | ATR 부재 시 폴백 |
| `PNF_REVERSAL_DEFAULT` | 3 | 전통적 3-box reversal |
| `PNF_MIN_COLUMNS` | 4 | 미만이면 원인이 축적됐다고 볼 수 없어 목표를 만들지 않는다 |

### 산출값 샘플

| price | ATR | 산출 box | 적용 규칙 |
|---:|---:|---:|---|
| 100.0 | 4.0 | 2.0 | ATR×0.5 (범위 내) |
| 100.0 | 1000.0 | 3.0 | 상한 클램프 (price×3%) |
| 100.0 | 0.01 | 0.5 | 하한 클램프 (price×0.5%) |
| 200.0 | 없음 | 2.0 | 폴백 (price×1%) |

## 폴백 조건 — 억지 목표 생성 금지 (C5)

다음 중 하나라도 해당하면 `measured_objective()`는 **`None`을 반환**하고 기존 구조 레벨 목표를 그대로 쓴다. 추정치를 만들지 않는다.

- 축적 구간(TR)이 없거나 지지/저항 가격이 불완전
- 지지 ≥ 저항 (구간이 성립하지 않음)
- 박스 크기를 산출할 수 없음(가격 ≤ 0 등)
- TR 대역 안의 열 수가 `PNF_MIN_COLUMNS` 미만
- 산출 목표가 카운트 라인·현재가보다 유리하지 않음
- 방향이 롱이 아님 (주식 페이퍼는 `long_only`이며 숏 목표는 검증 표본이 없다)

PNF는 구간을 **스스로 판정하지 않는다** — 와이코프 엔진이 이미 식별한 TR만 받는다. 이는 억지 판정 금지이자 "새 감지기가 아니다"라는 경계(C2)를 코드로 강제하는 장치다.

## 룩어헤드 금지 (C4)

`build_pnf_columns()`는 넘어온 캔들 순서를 그대로 신뢰하며 각 캔들은 자신보다 앞선 상태에만 영향을 준다. 호출자는 **확정 캔들만** 넘겨야 한다(주식 경로는 저장된 확정 일봉을 사용).

회귀 가드: `tests/test_pnf_target.py::test_columns_depend_only_on_past_candles` — 접두사로 만든 열이 전체로 만든 열의 접두사여야 한다. 미래 봉이 과거 열 구성에 영향을 주면 이 불변식이 깨진다.

## 목표 편입 규칙 — PNF가 항상 이기지 않는다

`stock_paper/targets.py::merge_pnf_target`

편입 조건(전부 만족해야 채택):
1. PNF 목표가 산출됨
2. 현재가 기준 유리한 방향
3. **기존 최원거리 목표보다 멀다** — 가까우면 기존이 이미 더 보수적이므로 유지

| 상황 | `target_source` | 결과 |
|---|---|---|
| PNF 채택 | `structure_levels+pnf_measured_objective` | 상위 TP로 추가 |
| 구조 목표가 더 멂 | `structure_levels` | 기존 유지, `skip_reason=structure_target_farther` |
| 불리한 방향 | `structure_levels` | 기존 유지, `skip_reason=not_favorable` |
| 산출 불가 | `structure_levels` | 기존 유지, payload 없음 |

채택되지 않아도 **산출값 자체는 보존**해 A/B 비교에 쓴다.

## RR 정의 — 가중 방식과 병기

`stock_paper/risk_reward.py`

```
reward_weighted = Σ (TPᵢ 거리 × 배분비율ᵢ)      # 비율은 사용 가능한 목표 수로 정규화
rr_weighted     = reward_weighted / risk
```

기본 배분 40/35/25. 시나리오 빌더가 목표를 최대 2개까지만 만들므로 **정규화가 정상 경로**다(3개 비율을 2개 목표에 그대로 쓰면 합이 1 미만이 되어 보상이 다시 과소집계된다).

병기되는 값:

| 키 | 의미 |
|---|---|
| `rr_ratio` | 게이트가 사용하는 정본 = 가중 RR |
| `rr_ratio_first_target` | 기존 TP1 단독 기준 (회귀 비교 기준선) |
| `rr_detail` | 위험·보상·목표 수·사용된 배분비율 (감사 흔적) |
| `rr_ab` | `{with_pnf, structure_only, first_target_only}` — A/B 기록 |

**임계 `min_rr`는 1.5로 불변이다(C1).** 이 WO는 분자를 정합화할 뿐 기준을 낮추지 않는다.

### 정직한 고지 — 통과율은 올라간다

가중평균은 TP1 이상이므로 **통과율이 오르는 방향인 것은 산술적으로 당연하다**. 결정론적 민감도 그리드(`scripts/measure_rr_definition_shift.py`, 105조합) 결과:

- 기존 정의 통과 33/105 (31.4%) → 가중 정의 통과 51/105 (48.6%)
- 새로 거부 0건 (가중평균 ≥ TP1이므로 당연)

정당화 근거는 "기준을 낮췄다"가 아니라 **"분자가 틀렸었다"**이다. 다만 무차별 통과는 아니다 — NVDA 사례는 TP2가 TP1의 3배여도 RR 1.02로 여전히 거부된다.

**이 변경이 성과를 개선하는지는 이 표로 알 수 없다.** 청산 표본이 0이므로 승률·실현 R 판정은 불가하며, 표본이 쌓인 뒤에만 판정 가능하다.

## A/B 기록 규격 (작업 4)

같은 후보에 대해 두(세) 정의의 RR을 **동시에 저장**한다. 진입은 하나지만 기록은 여럿이며, 이것이 "PNF가 실제로 나은가"에 답하는 유일한 정직한 방법이다.

```json
"rr_ab": {
  "with_pnf": 2.41,          // PNF 목표 포함 가중 RR (게이트 사용)
  "structure_only": 1.62,    // 구조 레벨만의 가중 RR
  "first_target_only": 0.98  // 기존 TP1 단독 RR
},
"target_source": "structure_levels+pnf_measured_objective",
"pnf_measured_objective": { "target_price": ..., "count_columns": ..., "adopted": true }
```

## 검증 레일 (C3)

- PNF 목표를 **실제로 채택한** 진입만 `wyckoff:pnf_measured_objective` candidate 시그니처로 등록된다. 채택되지 않은 산출은 등록하지 않는다(관측되지 않은 목표를 원장에 넣지 않는다).
- `engine="wyckoff"`를 재사용한다 — 새 감지기가 아니라 기존 와이코프 국면의 목표 계산기이기 때문이다(C2).
- 승격은 N≥30·CI 하한 충족 + 제안-거부권 경유. **그전까지 PNF는 후보 상태로 관측만 된다.**

## 현재 한계 (반드시 함께 읽을 것)

1. **주식 청산 경로가 존재하지 않는다.** `StockOrder` 생성은 `service.py`의 `side=Side.BUY` 한 곳뿐이며 SELL 주문을 만드는 코드가 전 코드베이스에 없다. 따라서 PNF 목표에 도달해도 청산되지 않고, **목표 도달률·실현 R을 채점할 수 없다.**
2. 그 결과 이 WO의 효과 측정은 **청산 경로가 생긴 뒤에야** 가능하다.
3. 시장 백테스트(작업 5)는 실히스토리 DB가 있는 환경에서 별도 수행해야 한다.
