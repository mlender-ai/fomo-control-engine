# 출구 A/B 반사실 대조 (WO-FCE-WHALE-EXIT-REPLAY-01)

구현: `backend/app/paper/whale_exit_replay.py` · 테스트: `backend/tests/test_whale_exit_replay.py`

## 답 — 우리 출구가 손실의 대부분을 만들었다

```
                출구 A (현행)    출구 B (고래 청산 추종)
실현              −14.9644            −2.5455
승률                 35.1%              37.8%
PF                    0.50               0.89

차이(B−A) +12.4189 USDT · 대조 37/37건
선행: 우리가 먼저 27건 · 고래가 먼저 10건
```

**우리가 27/37건에서 고래보다 먼저 나왔다.** 고래 청산까지 기다렸으면 손실이 83% 줄었다.

## 원인은 단일 사유다 — `time_decay`

| 구분 | 건 | A 실현 | B 실현 | 차이 |
| --- | --- | --- | --- | --- |
| **`ours_first` / `time_decay`** | **21** | **−7.3105** | **+4.7399** | **+12.0504** |
| `whale_first` / `invalidation_breach` | 1 | −4.7716 | −0.0391 | +4.7326 |
| `ours_first` / `invalidation_breach` | 2 | −5.9387 | −4.3297 | +1.6090 |
| `ours_first` / `breakeven_stop` | 3 | −0.0885 | −0.4657 | −0.3772 |
| `ours_first` / `take_profit_2` | 1 | +3.4149 | +1.7538 | −1.6612 |
| `whale_first` / `time_decay` | 9 | −0.2700 | −4.2046 | −3.9346 |

**전체 차이 +12.42 중 +12.05 가 `ours_first/time_decay` 하나에서 나온다.** 손절도 신호도
아니고 **시간 만료가 이익 날 포지션을 잘랐다** — 그 21건은 A 에서 −7.31 인데 B 에서 +4.74 로
부호가 뒤집힌다.

## 그런데 그 `time_decay` 는 정상 발화가 아니다

```
symbol    보유봉  사유         실경과시간
SOLUSDT   30     time_decay   3.20h
HYPEUSDT  30     time_decay   0.51h
SOLUSDT   30     time_decay   1.08h
ETHUSDT   30     time_decay   0.18h
SOLUSDT   30     time_decay   0.00h      ← 진입 직후 시간 만료
```

`holding_bars=30`(상한)인데 **실경과가 0.18~4.0시간**이다. 4시간봉 30개면 **120시간**이어야
한다. `holding_bars` 가 봉이 아니라 **잡 실행 횟수**를 세고 있다.

### 기전

```python
whale_follow.py:728
if bar is None or bar.timestamp <= trade.entry_bar_at:   # 진입봉만 비교한다
```

가드가 **마지막 평가봉을 기억하지 않는다.** 추종 잡은 900초 주기 + 체결 구동이라 같은 봉을
여러 번 평가하고, 그때마다 `apply_exit_decision` 이 `holding_bars += 1` 을 한다.
상한 30 이 설계 의도(5일)의 **1/30 시점**에 채워진다.

**37건 중 36건이 이 결함의 영향을 받았다.**

`WHALE-FOLLOW-01` Phase 6 에서 들어온 결함이다.

## 그래서 판정은 "전환하라"가 아니다

이 비교는 **"우리 사다리 대 고래 청산"이 아니라 "버그 있는 사다리 대 고래 청산"** 이다.
그 구분 없이 출구를 고래 추종으로 전환하면 **버그를 설계로 굳히게 된다.**

```
verdict: EXIT_B_BETTER
actionable: False
caveat: 출구 A 에 결함이 있다 — holding_bars 가 봉이 아니라 잡 실행 횟수를 센다(36건 확인).
        출구를 전환하기 전에 그 결함부터 고치고 다시 대조해야 한다.
```

`test_exit_a_defect_blocks_the_switch_recommendation` 이 이 안전장치를 고정한다.

### 이 WO 는 출구 A 를 고치지 않았다 (C4)

비교 대상이 바뀌면 비교가 무의미해진다. **결함 수리 → 재대조**가 순서이며 수리는 별건이다.

## 반사실이지 포지션이 아니다 (C1·C2)

출구 B 는 **계산만 한다.** 같은 진입에 실제 포지션을 둘 열면 리스크가 두 배가 되고 표본도
이중 계상된다.

| | |
| --- | --- |
| 공식 표본 | **출구 A 하나** (`whale_follow` 트랙) |
| 출구 B | 병기 필드 · 트랙 판정에 합산하지 않음 |
| 원장 쓰기 | **0건** — `test_module_never_writes_a_position` 이 고정 |

비용 모델은 출구 A 와 **같은 정책 객체**에서 읽는다. 비용이 다르면 A/B 차이가 출구 차이인지
비용 차이인지 갈리지 않는다.

## 만들 수 없으면 만들지 않는다

| 상황 | 처리 |
| --- | --- |
| 고래가 아직 보유 중 | `exit_b_net = None` · `lead = whale_open` |
| 고래 체결가 미상 | `exit_b_net = None` · 선행 판정만 남김 |

## 화면 응답 시간

두 블록을 고래 탭에 붙이면서 (지갑, 심볼)당 조회가 거래 수만큼 나갔다. 워커가 같은 SQLite
에 쓰는 동안 그 질의들이 락을 기다려 탭 응답이 9~14초에서 14~29초로 늘었다. `EventCache`
로 (지갑, 심볼)당 한 번만 읽게 바꿔 블록 자체는 0.85s → 0.65s 가 됐다.

**남은 9~15초는 이번 변경 이전부터 있던 것이다.** 이번 WO 범위가 아니라 그대로 두고 적어
둔다 — 진단 화면이 느려서 안 보게 되면 진단이 없는 것과 같으므로 별도로 다뤄야 한다.
