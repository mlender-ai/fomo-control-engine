## 0. 문제 — 7개가 다 살아있을 때와 4개만 살아있을 때가 구분되지 않는다

```python
confluence.py:145   long_score = round(sum(item["score"] for item in long_evidence), 2)
```

**단순 합이다.** `backend/app/analyst/confluence.py` 전체에서 `coverage` ·
`available_engines` · `missing` 이 등장하는 횟수는 **0회**다.

침묵한 엔진은 양쪽에 0을 기여하고 끝난다. 그래서 **모든 엔진이 판정한 상태와 절반이 침묵한
상태가 같은 점수 체계에서 비교된다.**

**N=1 이다.** 이 한 건이 예외인지 상시인지는 Phase 0 분포가 나와야 안다.

## 1. 이미 있는 선례 — 신설이 아니라 이식이다

```python
lifecycle.py:296   if judged < 3:
                       return f"관측 보류: 판정 가능 모듈 {judged}/7 — 구조 형성 대기"
```

**보유 포지션 경로에는 이미 커버리지 게이트가 있다.** 스카우트 경로에만 없다.
Phase 2 는 이 선례를 이식하는 것이지 새 개념을 만드는 것이 아니다.

## 2. 임계 3종 — 전부 미정 (사용자 결정)

| # | 축 | 현재 | 제안 | 확정값 |
|---|---|---|---|---|
| 1 | **최소 판정 가능 엔진 수** | 게이트 없음 | 보유 포지션 선례는 3 | **미정 — 사용자 결정** |
| 2 | **최대 허용 침묵 가중 비율** | 게이트 없음 | 실측 사례 28.7% | **미정 — 사용자 결정** |
| 3 | **`MIN_DIRECTIONAL_EVIDENCE` 병행 임계** | 항목 3개 | 서로 다른 엔진 2개 이상 | **미정 — 사용자 결정** |

### 축 3 — 왜 항목 수로는 부족한가 (E2)

```python
confluence.py:12    MIN_DIRECTIONAL_EVIDENCE = 3
confluence.py:995   if len(long_evidence) + len(short_evidence) < MIN_DIRECTIONAL_EVIDENCE:
```

**증거 항목 수**를 센다. 와이코프 한 엔진이 국면 1건 + 마커 N건을 내므로 **엔진 하나가 단독으로
이 최소치를 충족할 수 있다.** "3개 근거"라는 표현이 실제로는 "1개 엔진"일 수 있다.

Phase 2 는 항목 수 검사를 **유지한 채** 엔진 수 검사를 추가한다(둘 다 통과해야 함). 기존
검사를 대체하면 그건 완화이고, C1 이 금지한다.

### 임계를 지금 못 정하는 이유

세 값 모두 **분포를 봐야 정할 수 있다.** 예를 들어 판정 가능 엔진 수가 실측에서 대부분
4~5에 몰려 있다면 임계 5는 사실상 전면 차단이고, 임계 2는 사실상 무게이트다. 분포 없이
숫자를 고르면 그 숫자는 근거가 아니라 취향이다.

## 4. Phase 2 가 할 일 (아직 하지 않았다)

1. 커버리지(판정 가능 엔진 수 · 침묵 가중 · 침묵 비율)를 confluence 산출물에 **추가**
2. 임계 미달 시 stance 를 `insufficient` 로 **강등** — 승격은 없다(C3·C5)
3. `MIN_DIRECTIONAL_EVIDENCE` 에 엔진 수 검사 **병행**
4. 강등 사유 조회 노출 (C9 침묵 금지)

**착수 조건**: 결정 1(검증 창 처리) 확정 + 결정 3(이 문서의 임계 3종) 확정.
둘 중 하나라도 미정이면 Phase 2 는 착수하지 않는다.
