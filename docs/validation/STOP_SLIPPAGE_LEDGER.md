## 2. 반사실 — 스톱이 −1.0R 로 체결됐다면

손절 49건만 정확히 −1.000R 로 바꾸고 나머지는 원장 그대로 둔다.

| | N | 합계 | 거래당 | 95% CI |
| --- | ---: | ---: | ---: | --- |
| 실제 (종가 체결) | 153 | **−42.658R** | −0.2788 | [−0.532, −0.033] |
| 반사실 (스톱 −1.0R) | 153 | **+14.835R** | +0.0970 | [−0.056, +0.254] |
| 차이 | | **+57.49R** | | |

**정직하게 읽어야 한다.** 이 표가 말하는 것은 "고치면 번다"가 아니다.

- 실제는 CI 가 통째로 0 아래 — **지는 것이 통계적으로 확정**이다.
- 반사실은 CI 가 0 을 **가로지른다** — 이기는 것이 아니라 **지는 것이 확정이 아닌 상태**다.

즉 스톱 체결 수리는 **증명된 손실을 제거**하지, 우위를 만들어 내지 않는다.
우위는 그 다음 문제다.

### 그리고 intrabar 가 57.49R 을 다 회수하지는 못한다

`stop_fill_mode="intrabar"` 는 무효화 가격에 체결하되 **갭이면 시가**에 적는다.
위 5.71× · 3.98× 같은 건은 갭 성분이 섞여 있어 시가 체결로도 −1.0R 을 넘는다.
그래서 57.49R 은 **상한**이고, 실현치는 그보다 작다. 얼마나 작은지는 종료봉 OHLC 가
있어야 산출되는데 운영 원장에 4h 캔들이 남아 있는 심볼은 3개(BTC·ETH·SOXL)뿐이라
이 원장만으로는 닫을 수 없다.

## 2-B. 그런데 재판정은 **반대로** 말한다 — 출하된 intrabar 를 지지하지 않는다

§2 의 반사실은 "손절이 −1.0R 로 체결됐다면"이라는 **산술 치환**이다. 실제 엔진을
`stop_fill_mode` 만 바꿔 다시 돌리면 이야기가 달라진다.

```
scripts/paper_replay_report.py --database fomo_control_engine.db   (crypto-v3 정책)
```

| 심볼 | 봉 | 현행(종가 손절) | 반사실(봉 중간) | 차이 | 손절 건수 |
| --- | ---: | ---: | ---: | ---: | --- |
| BTCUSDT | 2,196 | **+18.328R** (N=126) | +9.394R (N=148) | **−8.934R** | 36 → 54 |
| ETHUSDT | 2,196 | −24.936R (N=187) | **−21.188R** (N=235) | **+3.748R** | 72 → 119 |
| SOXLUSDT | 969 | 0 (N=0) | 0 (N=0) | 0 | 0 → 0 |
| **합계** | | **−6.608R** | **−11.794R** | **−5.186R** | 108 → 173 |

**합계 기준으로 intrabar 가 5.186R 나쁘다.** BTC 는 강하게 반대(−8.9R), ETH 는 약하게
찬성(+3.7R). 부호가 갈린다.

### 왜 §2 와 반대인가 — 종가 체결에는 **공짜 옵션**이 붙어 있다

종가 체결은 무효화가를 봉 중간에 뚫어도 **종가가 되돌아오면 손절 자체가 없던 일이 된다.**
손절 건수가 그 증거다 — BTC 36 vs 54, ETH 72 vs 119. 봉 중간 체결은 그 되돌림 건을
전부 손실로 확정한다.

그래서 두 체결 규칙의 거래는 **같은 모집단이 아니다.**

| | 손절 빈도 | 손절 1건당 |
| --- | --- | --- |
| 종가 체결 | 적다 (되돌림은 면제) | **−2.173R** (원장 실측) |
| 봉 중간 체결 | 많다 (되돌림도 확정) | 대략 −1.0R + 갭 |

§2 는 두 번째 열만 고쳤고 첫 번째 열을 고정했다. 그래서 +57.49R 이 나왔다.
재판정은 두 열을 **동시에** 움직인다. 그래서 −5.186R 이 나왔다.

**재판정 쪽이 맞다.** 실제로 스톱 주문을 걸면 되돌림 면제는 살 수 없다.

### 결론 — `stop_fill_mode=intrabar` 는 근거가 뒤집혔다

WO-FCE-NET-EDGE-01 은 이 축을 **합성 픽스처에서** 채택했고, 운영 캔들 재판정에서는
**합계가 음수**다. 현재 근거 상태:

| 근거 | intrabar 판정 |
| --- | --- |
| 합성 픽스처 N=11 | 찬성 (출하 사유) |
| 운영 캔들 재판정 (BTC+ETH) | **반대 −5.186R** (BTC −8.9 / ETH +3.7, 부호 갈림) |
| 운영 원장 반사실 §2 | 찬성 +57.49R — 단 **손절 빈도를 고정한 산술 치환**이라 과대 |

**권고: 되돌리지 말고 판정을 유보한다.** 되돌리면 안 되는 이유가 따로 있다 —
종가 체결의 "되돌림 면제"는 **라이브에서 재현되지 않을 수 있다.** 실제로 스톱 주문을
걸면 면제가 없고, 걸지 않으면 원장이 보여준 −2.173R 을 문다. 즉 종가 체결의 +18.3R 은
**실행 가능하지 않은 수익일 가능성**이 있다. 이건 파라미터 문제가 아니라
**라이브 주문 방식이 무엇인지**의 문제이며, 코드가 아니라 사장님 결정 사항이다.

> 판단에 필요한 질문 하나: **라이브에서 스톱 주문을 거래소에 미리 걸 것인가,
> 아니면 봉 종가마다 엔진이 보고 시장가로 닫을 것인가?**
> 전자면 intrabar 가 유일하게 정직한 모델이고 BTC 의 +18.3R 은 애초에 없는 돈이다.
> 후자면 종가 체결이 맞는 모델이고, 대신 원장의 −2.173R/건 을 계속 문다.

## 3. 마찰 상한 0.16 은 실측상 최선이지만 **유의하지 않다**

왕복 비용률 = `(taker 0.06 + slippage 0.03) × 2 = 0.180%`
비용R = `왕복 비용률 / 스톱거리%`

```
비용R 실측: N=155  min=0.0246  p25=0.0689  중앙=0.1078  p75=0.1344  max=0.4221  평균=0.1123
```

| 임계 | 거부 | 잔존 N | 거래당 netR | 95% CI | 판정 |
| --- | ---: | ---: | ---: | --- | --- |
| (없음) | 0 | 153 | −0.2788 | [−0.530, −0.033] | 기준 |
| 0.20 | 8 (5.2%) | 146 | −0.2780 | [−0.543, −0.025] | 개선 (비유의) |
| **0.16** | 26 (16.8%) | 128 | **−0.1970** | [−0.455, +0.056] | **개선 (비유의)** |
| 0.12 | 58 (37.4%) | 97 | −0.2321 | [−0.521, +0.058] | 개선 (비유의) |
| 0.08 | 105 (67.7%) | 50 | −0.3488 | [−0.781, +0.066] | **악화** |

거부되는 코호트 자체는 확실히 나쁘다 — `비용R>0.16` 25건이 **거래당 −0.6977R**,
통과분 128건은 −0.1970R. 그런데 부트스트랩 CI 는 기준과 크게 겹친다.

**결론: 출하된 0.16 은 네 후보 중 argmax 이고, 조이면 악화한다.
유지하되 "검증됨"이라고 부르지 않는다.** 0.08 이 악화한다는 사실은 방향성 있는
정보다 — 마찰만 보고 자르면 좋은 자리까지 잘린다.

## 6-B. 스윕 명령이 **끝나지 않는다** — 이게 지금 가장 실무적인 막힘이다

WO-FCE-NET-EDGE-01 은 임계 결정을 호스트 스윕에 맡기고 이 명령을 남겼다.

```bash
PYTHONPATH=. python3 scripts/paper_replay_report.py --database <db> --sweep
```

이 호스트에서 실측한 소요:

| 실행 | 축 | 심볼 | 결과 |
| --- | ---: | --- | --- |
| 전체 스윕 (문서가 지시한 그대로) | 23 | 3 | **50분 타임아웃 · 출력 0바이트** |
| 반사실만 (`--sweep` 없이) | 2 | 3 | 약 30분 완주 |
| 축 5개로 축소 | 5 | BTC 1개 | **2시간 06분에도 미완** |

23축 × 3심볼은 이 기계에서 **하루 단위**다. 즉 문서가 지시한 명령은 실행 가능하지 않다.

부수적으로 두 가지가 같이 드러났다.

1. **출력이 블록 버퍼링된다.** 파일로 리다이렉트하면 타임아웃에 죽을 때 이미 계산된
   심볼 결과까지 통째로 사라진다. 첫 시도가 0바이트였던 이유다. `python3 -u` 가 필요하다.
2. **기준선을 착각하기 쉽다.** 로더가 `params/` 에서 최고 버전을 고르므로 기준선은
   이미 crypto-v3 다. 여기에 `stop_fill_mode=intrabar` 같은 축을 "켜는" 방향으로 주면
   전 축이 no-op 이 되어 **"효과 없음"이 일제히 뜬다.** 이걸 "유의한 축이 없다"로 읽으면
   정반대 결론에 도달한다. 축은 **v2 값으로 되돌리는 방향**으로 줘야 한다.

> 수리 제안 (별건): `scripts/paper_replay_report.py` 에 `--axis` 선별 옵션과
> 심볼별 중간 저장, 그리고 `-u` 강제. 지금은 전부 아니면 전무다.

**1·2·3 모두 캔들 부족이 공통 원인이다.** 그리고 이 부족은 **악화 중**이다.

```
stance_history_candles 전량
  2026-08-21 (CANDLE_SUPPLY.md 실사) : 5,577행
```
