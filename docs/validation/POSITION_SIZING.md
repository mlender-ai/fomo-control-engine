## 0. 먼저 — WO 가 인용한 두 숫자가 재현되지 않았다 (C9)

WO §1 은 이렇게 시작한다:

```
R 합계   +0.88R   (양수)
금액     −47.28 USDT   (음수)
부호가 반대다.
```

**같은 기준으로 재산출하면 부호는 반대가 아니다.**

| 기준 | R 합계 | 금액 합계 | 부호 |
| --- | --- | --- | --- |
| gross | **+1.190R** | **−29.70** | **반대** |
| net | **−2.747R** | **−47.06** | 같음 |

`+0.88R` 은 **gross** 계열 값이고 `−47.28` 은 **net** 값이다. WO 는 둘을 나란히 놓았다.

> **부호 역전 현상 자체는 실재한다** — 단 gross 안에서다(+1.190R vs −29.70 USDT).
> 그러므로 이 WO 의 **기전 진단(사이즈 왜곡)은 유효하고 수리도 유효하다.**
> 다만 §1 의 두 숫자를 그대로 인용하면 안 된다.

### N 도 다르다 — 31 → 32

Phase 1(8/16) 이후 **거래 1건이 추가**됐다. 별도로 `policy_invalid:pre_tp_pressure_exit`
태그 1건(ETHUSDT)이 있다. Phase 1 의 `승 16 / 패 15` 는 이 표본에서 재현되지 않았다
(net 기준 17/15 · gross 기준 18/14). **Phase 1 의 per-trade R 값을 재현하지 못했다.**

이 문서의 모든 수치는 **net 기준**이며 정의는 다음과 같다:

```
계획 리스크 = |진입가 − 무효화가| × 수량
R          = net_pnl_usdt / 계획 리스크
```

## 1. 진단 — 1R 의 금액가치가 상수가 아니다

```python
policy.py  notional = margin_usdt(100) × leverage(3) = 300   # 고정
           quantity = notional / bar.close                    # 스톱 거리와 무관
```

수량이 스톱 거리와 무관하므로 **1R 의 금액가치가 스톱 거리에 비례한다.**

| | 값 |
| --- | --- |
| 1R 금액 최소 | 2.434 |
| 1R 금액 중앙 | 4.650 |
| 1R 금액 최대 | 14.992 |
| **변동계수(CV)** | **0.5218** |
| 최대/최소 | **6.16배** |

그리고 **지는 거래의 스톱 거리가 1.277배 크다.**

| | N | 평균 R | 평균 스톱거리 | 평균 1R 금액 | 평균 손익 |
| --- | --- | --- | --- | --- | --- |
| 승 | 17 | +0.815R | 1.562% | 4.687 | +4.00 |
| 패 | 15 | −1.107R | 1.996% | 5.987 | −7.67 |

스톱거리 비와 1R 금액 비가 **둘 다 정확히 1.277배**다 — 1R 금액이 스톱 거리에
비례한다는 것의 직접 증거다. R 로는 대칭에 가까운데 금액으로는 지는 쪽이 크다.

## 2. 수리 — 수량을 리스크에서 역산한다

```
수량 = 리스크 예산 / |진입가 − 무효화가|
→ 1R 금액 = 스톱 거리 × (예산 / 스톱 거리) = 예산 (상수)
```

`plan_position_size()` (`backend/app/paper/policy.py`). 기본값은 `fixed_notional`(기존 동작)이고
`params/crypto-v2.json` 의 `sizing_mode` 로 옵트인한다 — **파일을 지우면 즉시 되돌아간다.**

### R 불변 — 수용 기준 1

수량이 s 배가 되면 손익도 계획 리스크도 같이 s 배가 되므로 R 은 불변이다.
실제 코드 경로로 32건 전체를 통과시켜 확인했다:

```
R 합계 전 −2.746826 · 후 −2.746826 · 차이 4.44e-16   (부동소수점 오차)
거래별 R 최대 차이 4.44e-16
```

**사이즈 변경이 R 회계로 새어 들어가지 않았다.**

## 4. 이 수리가 하지 않는 것 — 손실은 남는다

```
금액 −47.06 → −6.87 USDT   (손실 85% 축소)
PF   0.5909 → 0.8346       (여전히 1.0 미만)
```

**PF 는 여전히 1 미만이다. 기대값은 음수 그대로다.** 사이징은 R 회계와 금액 회계를
일치시킬 뿐이며, R 자체가 음수(−2.747R)이므로 금액도 음수로 남는다:

```
금액 = R 합계 × 예산 = −2.747 × 2.5 = −6.87   (검산 일치)
```

> **이것은 성과 개선책이 아니라 정합 수리다.** WO §1 의 표현이 정확하다.

## 5. 사이징을 고치면 무엇이 구속 조건이 되는가 — **비용이다**

R 단위로 분해하면:

| | R |
| --- | --- |
| gross 우위 | **+1.190R** |
| 마찰 비용 | **−3.937R** |
| net | **−2.747R** |

**비용이 gross 우위의 3.31배다.**

그리고 비용의 R 값은 **사이즈와 무관하다** — 사이즈가 약분되기 때문이다:

```
비용R = 비용률 / 스톱거리%
```

| 심볼 | 스톱거리 | 실측 비용R | 이론값 |
| --- | --- | --- | --- |
| BTCUSDT | 0.811% | 0.2216 | 0.2219 |
| ETHUSDT | 0.816% | 0.2196 | 0.2205 |
| SPCXUSDT | 3.903% | 0.0460 | 0.0461 |

평균 **0.1230R/건**. 32건이면 3.937R.

> **스톱이 좁을수록 비용이 R 을 더 많이 먹는다.** 스톱 0.8% 거래는 진입하는 순간
> 0.22R 을 잃고 시작한다. 사이즈를 어떻게 잡아도 이 값은 변하지 않는다.

`EXPECTANCY-01` Phase 2 는 "비용은 주범이 아니다"(손익비 0.590 → 0.552, −6.4%)라고 봤다.
**금액 손익비 기준으로는 맞지만 R 기준으로는 틀렸다** — 비용이 gross 우위의 3배가 넘는다.
사이즈 왜곡이 제거되고 나면 비용이 남는 유일한 구속 조건이다.

**후속 대상**: 비용률(`taker_fee_pct` 0.06 + `slippage_pct` 0.03) 의 현실성,
좁은 스톱 거래의 진입 억제, 왕복 진입 제거(Phase 3).
**이 WO 의 Phase 1 범위 밖이며 아무것도 고치지 않았다.**

## 6. 원장 기록 (C10)

`target_plan.sizing` 에 거래별로 남는다:

```json

  "quantity": 3.05, "notional_usdt": 308.0, "margin_usdt": 102.7,
  "stop_distance": 0.82, "stop_distance_pct": 0.811,
  "risk_budget_usdt": 2.5,

```

`constraint` 는 `none` · `max_notional` · `min_notional` · `mode:fixed_notional` ·
`fallback:no_stop_distance`. **상한·하한에 걸리면 `planned_risk_usdt` 는 예산이 아니라
실제 리스크를 적는다** — 상한에 걸린 건은 예산보다 작고, 거래소 최소 주문에 걸린 건은
예산보다 **크다.** 그 사실을 숨기지 않는다.

### 최소 주문 단위

`min_notional_usdt` 로 처리한다. 이 경우 **리스크가 예산을 넘는다** — 반올림으로 리스크가
예산을 초과하지 않게 하려면 진입을 거르는 편이 맞지만, 그것은 **진입 건수를 바꾸므로
C1 위반**이다. 이 Phase 에서는 기록만 하고 넘긴다. 이 표본에서는 0건이다.
