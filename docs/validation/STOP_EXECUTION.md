## 0. 결론 — 손절과 익절의 체결 규칙이 비대칭이다

```python
policy.py:360  def _stop_breached(trade, close):          # ← 종가만 본다
                   return close <= trade.stop_price

policy.py:366  def _take_profit_touched(trade, bar):      # ← 봉 중간 터치를 본다
                   return bar.high >= trade.take_profit_price
```

**익절은 봉 중간에 닿으면 그 가격에 체결되고, 손절은 봉이 닫힐 때까지 기다렸다가
종가에 체결된다.** 4시간봉에서 종가는 무효화선에서 멀리 가 있다.

이 비대칭이 초과분의 기전이다. 슬리피지 모델(`execution_cost_rate`)의 문제가 아니다 —
비용은 따로 계산되며 초과분의 18%밖에 안 된다.

## 1. −0.559R 이 어디서 오는가 (§5 작업 1)

먼저 WO 가 인용한 `−1.559R` 의 기준을 확정한다. **gross 값이다.**

| | 값 |
| --- | --- |
| 평균 grossR | **−1.559** (WO 인용값과 일치) |
| 평균 비용R | +0.122 |

계획은 −1.000R 이다. 분해:

| 요인 | R | 비중 |
| --- | --- | --- |
| **체결가가 무효화선 너머** | **−0.559** | **82%** |
| 마찰 비용 | −0.122 | 18% |
| 합계 (netR − 계획) | −0.681 | 100% |

**초과분의 82%가 체결가 이탈이다.** 비용은 부차적이다.

## 3. 산출하지 못한 것 (C9)

**종가 체결 규칙과 갭의 분리는 산출하지 못했다.**

필요한 것: 청산 봉의 OHLC. "무효화선에 봉 중간에 닿았는가, 아니면 봉 시가부터 이미
넘어 있었는가"는 `low`/`high`/`open` 없이는 판정할 수 없다.

```
market_snapshots          → 크립토 OHLC 없음
toss_candles              → 주식 전용
stance_history_candles    → 국면 판정용, 체결 검증에 부적합
```

**크립토 봉은 DB 에 보존되지 않는다 — 거래소에서 실시간 조회한다.** 그래서 사후 체결
검증이 원장만으로는 불가능하다. `POSITION_VIEW-01` 이 발견한 "국면이 저장되지 않아
사후 검증 불가"와 **같은 종류의 결함**이다.

추정치를 만들지 않았다. 요인별 정확한 기여도(갭 vs 종가 규칙 vs 감지 지연)는
**거래소 봉 조회 후에만 산출 가능하다.**

## 4. 대응 방향 (§5 작업 3~5) — 적용하지 않았다

**지배 요인은 종가 체결 규칙이다**(구조적으로 확인). 대응 방향:

### 손절도 봉 중간 터치로 체결한다

```python
# 지금            close <= stop_price          → 봉이 닫힐 때까지 기다린다
# 제안            bar.low <= stop_price        → 익절과 같은 규칙
```

- **무효화 임계를 완화하지 않는다.** 같은 가격에서, 더 일찍 체결될 뿐이다 (C1 정신 준수)
- **실제 손절 주문이 하는 일이 이것이다.** 지금 모델은 손절을 "종가 시장가"로 취급하는데
  실계좌의 스톱 주문은 봉 중간에 체결된다
- 익절은 이미 봉 중간 터치다. **모델의 비대칭이 사라진다**

> ⚠️ 종가 기준에는 **장점도 있다** — 꼬리에 털리지 않는다. 봉 중간 터치로 바꾸면
> 지금은 살아남아 이익으로 끝난 거래 일부가 손절로 바뀐다. **순효과는 반사실 없이는 모른다.**

### 갭 (SPCXUSDT)

봉 중간 터치로 바꿔도 갭은 남는다. 갭은 **수리 대상이 아니라 리스크 예산에 반영할
상수**다(WO §5 작업 4). Phase 4 와 함께 다룬다.

### 슬리피지 모델

`execution_cost_rate`(taker 0.06% + slippage 0.03%)는 초과분의 18%만 설명한다.
**모델 수정이 지배적 대응이 아니다.**

## 5. 갭 / 종가 규칙 분리 — 산출했다 (Phase 4-2)

§3 은 "종가 체결 규칙과 갭의 분리는 산출하지 못했다"로 남겼다. 필요한 것이 **청산 봉의
OHLC** 라고 봤기 때문이다. 그것은 여전히 없다(크립토 봉 미보존). 그러나 분리는 OHLC 없이도
가능하다 — **초과분의 크기 자체가 판정 근거다.**

```
초과R = |체결가 − 무효화가| / 스톱거리
```

이 값이 1.0 을 넘으면 **한 봉이 스톱 거리 전체보다 더 멀리 무효화선을 지나쳤다**는 뜻이다.
종가 체결 규칙만으로는 그 크기가 나오지 않는다 — 봉 안에서 무효화선에 닿고 나서 종가까지
밀린 거리는 스톱 거리보다 작은 것이 정상이다.

| 구분 | N | 평균 초과R | 최대 초과R | 이탈% 범위 | 초과분 비중 |
| --- | --- | --- | --- | --- | --- |
| **갭** (초과R > 1.0) | **1** | **+2.510** | +2.510 | 11.948 | **56.1%** |
| 종가 규칙 (초과R ≤ 1.0) | 7 | +0.280 | +0.490 | 0.043 ~ 0.909 | 43.9% |

**두 군이 5배 간격으로 갈린다**(2.510 vs 0.490). 임계 1.0 은 그 사이 어디에 두어도 같은
분류가 나온다 — 임계 선택에 결과가 민감하지 않다.

### 여전히 산출하지 못한 것

- **갭 안에서 "시가부터 넘어 있었는가"** 는 판정 불가다. OHLC 가 필요하고 봉은 없다.
  즉 "주말 갭"인지 "봉 중간 급락"인지는 모른다
- **감지 지연**(워커가 봉 마감을 늦게 처리한 시간)의 기여도 분리 불가. 봉 타임스탬프와
  처리 시각의 차이가 원장에 없다
- **N=1 이다.** 갭의 빈도·크기 분포를 이 표본으로 말할 수 없다

정본: [`POSITION_SIZING.md`](POSITION_SIZING.md) §4-2 · 재산출 스크립트
`backend/scripts/risk_sizing_counterfactual.py`

> **손절 체결 규칙은 변경하지 않았다**(C4). §4 의 "봉 중간 터치" 제안은 여전히 반사실
> 미산출이며, 봉 보존 없이는 순효과를 알 수 없다.

## 6. Phase 2 이월 종결 — 반사실 경로가 생겼다 (WO-FCE-REPLAY-DEPTH-01 4-4)

§5 가 "적용은 반사실 이후다"라며 남긴 세 항목의 **실행 수단**이 생겼다. 봉이 저장되기
시작했고(`replay_history_backfill` · 기본값 꺼짐), 그 위에서 페이퍼 엔진을 재실행하는 하네스가 있다.

```bash
cd backend
PYTHONPATH=. python3 scripts/paper_replay_report.py --database ~/fomo_control_engine.db
```

출력은 같은 캔들·같은 정책 위의 두 행이다:

| | 손절 체결 규칙 |
| --- | --- |
| `현행(종가 손절)` | `close <= stop_price` — 라이브 `policy._stop_breached` 그대로 |
| `반사실(봉 중간 터치)` | `bar.low <= stop_price`, 체결가는 무효화가 |

차이는 체결 규칙 **하나뿐**이므로 gross·net·MDD·손절 건수의 차이가 전부 그 규칙에
귀속된다. §4 가 경고한 "지금은 살아남아 이익으로 끝난 거래 일부가 손절로 바뀐다"의
**순효과가 이 표에서 처음으로 관측된다.**

### 정책은 바뀌지 않았다

`paper/policy.py` diff **0줄**이다(C3). 봉 중간 터치 판정은 **하네스가** 내리며, 산출물에
`kind: "replay_counterfactual"` 이 붙는다 — 반사실이지 실적이 아니다(C9).

### 같은 봉에서 손절과 익절이 모두 닿았다면

봉 데이터로는 어느 쪽이 먼저였는지 알 수 없다. 하네스는 **손절을 먼저로 가정한다** —
리스크 관측에서 나쁜 쪽을 가정하는 것이 정직하다. 이 가정은 반사실을 보수적으로
만들며, 실제 개선 폭은 이 표보다 클 수 있다.

### 갭은 여전히 남는다

SPCXUSDT 12.5% 이탈은 봉 중간 터치로 바뀌어도 남는다 — 봉 시가부터 이미 넘어 있었다면
체결가는 무효화가가 아니라 그보다 나쁜 가격이다. 하네스는 무효화가 체결을 가정하므로
**갭 손실을 과소평가한다.** 갭은 수리 대상이 아니라 리스크 예산 상수이며
`POSITION_SIZING.md` 의 `gap_budget` 이 정본이다.

### 발표값 대조

§1 의 N=8 평균(gross −1.559 · 비용 +0.122 · net −1.681)은
`app/validation/published_values.py::stop_execution.phase2` 에 등록돼 있다.
`--compare-published` 를 붙이면 매 실행 원장에서 다시 계산해 대조하고, **어긋나면 종료
코드 1** 로 실패한다.

이 커밋은 경로다. 두 행의 실제 숫자는 **운영 DB 와 저장 히스토리가 있는 호스트에서**
