## 왜 필요했나

텔레그램에 오는 것은 건별 사건뿐이었다 — `엔진 진입 · HYPEUSDT 롱` · `엔진 청산 · net +4.33%`.
하루가 끝났을 때 **"지금 계좌가 얼마인가"** 에 답하는 메시지가 하나도 없었다.

`TRACK-CAPITAL-01` 이 화면에는 그 숫자를 만들었지만 텔레그램에는 오지 않았다.

## 계산하지 않는다 — 조립한다

| 값 | 출처 |
| --- | --- |
| 자본·실현·미실현 | `validation.track_capital` |
| 승률·PF·MDD | `paper.service._metric_payload` |
| 정지·차단·보류 | `poly_paper.track_status` · `stock_paper_tracks` |
| 조치 필요 | `pending_decisions` · `provisional_defaults` |
| 추종 대상 | `paper.whale_follow.performance_by_whale` |

`test_report_does_not_compute_its_own_metrics` 가 렌더러에 계산이 없음을 고정한다 —
`metrics.get("profit_factor")` 는 읽기이고 `gross_profit / gross_loss` 는 계산이다.
**중복 구현이 곧 두 개의 진실이다.**

## 두 개를 보내지 않는다 — 기존 블록을 대체했다

`PERFORMANCE-REPORT-01` 의 4트랙 성과 블록과 겹쳤다. 둘 다 트랙별 승률을 내는데
**N 이 달랐다:**

| 블록 | 크립토 청산 N |
| --- | --- |
| 기존 `format_paper_performance` | **70** |
| 5트랙 리포트 | **67** |

창 술어가 다르다. 같은 메시지에 N 이 다른 두 승률이 들어가면 서로를 설명하지 못하고,
그것이 `METRIC-TRUTH-01` 이 고친 결함이다(C3).

그래서 일일 요약에서는 리포트가 기존 블록을 **대체한다.** 리포트 산출이 실패하면 기존
블록으로 되돌린다 — 요약이 비는 것이 더 나쁘다. **주간 리포트는 기존 블록을 계속 쓴다.**

`content_summary_lines` 의 진입·폴리 줄도 뺐다(리포트가 낸다). **리더보드 줄은 남겼다** —
추적군 전체의 사후 채점이고 추종 트랙과 다른 것을 세므로 중복이 아니다.

## 관문을 지난다 — 이전에는 아니었다

`delivery_gate` 의 원칙은 "관문은 하나다" 인데 **일일 요약이 그 밖에서 직접 발송하고
있었다.** `daily_summary` 를 레지스트리에 등록하고 경유시켰다.

기본 차단(default-deny)이므로 등록 없이 경유시키면 요약이 사라진다 —
`test_daily_summary_is_registered_in_the_gate` 가 그것을 막는다.

## 하루 1회 · 따라잡기 유지

기존 슬롯(`maybe_send_daily_summary`)을 확장했다. 새 발송 주기를 만들지 않았다(C1).
`morning_summary_due` 의 따라잡기 판정(목표 시각 경과 + 당일 미발송)을 건드리지 않았다 —
분 단위 정확 일치로 하루가 통째로 사라진 전례가 있다.

## 하지 않는 것

| 금지 | 근거 |
| --- | --- |
| 트랙 총합 줄 | 통화가 다르고 판정이 독립이다(C5) |
| 실현·미실현 합산 | 확정과 미확정을 섞지 않는다(C4) |
| 막힌 트랙을 정상 표기 | 상태 줄이 성적을 대체한다(C7) |
| 길이 때문에 트랙 누락 | **항목을 줄이고 트랙은 남긴다**(C11) |
| N 미표시 | N<30 이면 태그, N=0 이면 성적 없음(C6) |
| 인과 단정 | 관측 서술만(C9) |

`test_긴_message_drops_items_not_tracks` 가 900자 한도에서도 5트랙이 전부 남음을 고정한다.

## 조치가 없으면 꼬리를 생략한다

매일 같은 경고가 붙으면 배경음이 된다. `action_lines([])` 는 빈 목록이고 그때 블록이
통째로 사라진다.
