# 고래 알림 승격 조건 (Whale Alert Promotion)

> WO-FCE-WHALE-ALERT-DEMOTE-01 Phase 4 정본.
> **이 문서는 결과를 보기 전에 커밋됐다.** 강등한 신호가 푸시로 되돌아오는 조건을
> 되돌아오고 싶어진 시점에 정하면, 그건 조건이 아니라 사후 합리화다.
> **배선하지 않는다.** 이 문서는 조건만 정의한다. 승격은 자동으로 일어나지 않는다(C4).

## 0. 지금 상태 — 강등

`whale_entry` 는 `app/notify/delivery_gate.py::DEMOTED_RULES` 에 있다. 텔레그램 개별 푸시
**0건**이다. 그 외에는 전부 그대로다:

| 경로 | 상태 |
|---|---|
| 온체인 체결 수집 (`app/onchain/`) | **유지** — 손대지 않았다(C2) |
| DB 원장 저장 | **유지** |
| 진단 API 조회 (`/api/paper/diagnosis` → `whale_observations`) | **유지 + 확장** — 미발송 건과 사유를 조회 가능(C3) |
| 일 1회 요약 1줄 | **신설** — 24h 집계만, 개별 건·지갑명 없음 |
| 텔레그램 개별 푸시 | **차단** |

강등의 근거는 빈도가 아니라 **검증 부재**다. 빈도를 조이는 접근(쿨다운·배치 창)은 선행 WO에서
이미 실패했다 — 배치 identity 에 체결 ID·건수가 들어가 `state_key` 가 매번 새로 생성됐고,
따라서 쿨다운이 **구조적으로 한 번도 적용된 적이 없었다.** 같은 지갑에서 6건이 같은 분에
도착한 것은 파라미터 문제가 아니었다.

## 1. 승격 조건 (전부 미정 — 사용자 결정)

아래 표의 임계값은 **하나도 확정되지 않았다.** 제안값은 논의의 출발점이며, 승인 전까지
승격은 일어나지 않는다.

| # | 축 | 종류 | 제안값 | 왜 이 축인가 |
|---|---|---|---|---|
| 1 | **사후 채점 표본 N** | 측정 | ≥ 30 (**미정 — 사용자 결정**) | N<30 에서는 승률 CI 폭이 결론을 못 낸다. 현행 관측 표본은 아래 §2 참조 |
| 2 | **승률 하한** | 측정 | 단독 수치 금지 — CI 하한 기준 (**미정 — 사용자 결정**) | 점추정 승률은 표본이 작을수록 낙관적으로 보인다. 이 저장소의 판정 규칙은 CI 비겹침이다 |
| 3 | **누적 R 하한** | 측정 | > 0 (**미정 — 사용자 결정**) | 승률이 높아도 누적 R 이 음수면 신호가 아니라 잡음이다. 두 축은 함께 봐야 한다 |
| 4 | **지갑당 발송 상한** | 정책 | 미정 (**사용자 결정**) | 승격해도 상한이 없으면 같은 스팸이 재발한다. 강등의 직접 원인이 무제한이었다 |
| 5 | **주기당 발송 상한** | 정책 | 미정 (**사용자 결정**) | 4와 같은 이유. 지갑별 상한만으로는 지갑 수가 늘면 총량이 다시 열린다 |
| 6 | **인적 승인** | 사람 | 1~5 전부 충족해도 사용자 명시 승인이 최종 조건 | 자동 승격 금지(C4). 미검증 신호를 푸시로 되돌리는 것은 코드가 정하지 않는다 |

### 축 2·3 — 왜 승률과 누적 R 을 따로 두는가

승률만 보면 작은 이익을 자주 내고 큰 손실을 가끔 내는 신호가 통과한다. 누적 R 만 보면
소수의 큰 적중이 다수의 실패를 가리는 신호가 통과한다. 둘 다 걸어야 둘 다 막힌다.

### 축 4·5 — 상한 없는 승격은 강등 이전으로 되돌아가는 것이다

승격 조건을 통과했다는 것은 "신호가 유효하다"는 뜻이지 "무제한 발송해도 된다"는 뜻이 아니다.
발송 상한은 신호 품질과 **독립적인** 별개의 결정이다.

## 2. 현재 관측 표본 — 결론을 낼 수 없다

WO 가 제시한 실측(2026-08-08 기준): **승률 20.0% · N=5 · 누적 -3.00R**.

**N=5 는 표본 부족이다.** 이 숫자로는 "고래 신호가 나쁘다"도 말할 수 없다 — 승률 20%의 95%
신뢰구간은 대략 0.5%~72% 로, 동전 던지기와 우수한 신호를 모두 포함한다. 강등의 근거는
"나쁘다는 증거"가 아니라 **"좋다는 증거가 없다"** 이며, 이 둘은 다르다.

일 1회 요약 1줄에도 같은 이유로 N<30 이면 "표본 부족"을 병기한다(C6).

## 3. 승격 절차 (배선 없음)

1. §1 의 6축 임계를 **사용자가 확정**하고 이 문서에 기록한다.
2. 확정된 임계에 대해 실측을 산출한다. 표본은 사후 채점 원장에서 나온다 — 수집은 이미
   계속되고 있으므로 강등 기간에도 표본은 쌓인다.
3. 전 축 충족 시 **사용자에게 보고**한다. 코드가 스스로 판정해 발송을 재개하지 않는다.
4. 사용자 승인 후에야 `DEMOTED_RULES` 에서 `whale_entry` 를 빼고 상한을 배선하는 별도 WO 를
   연다.

> 3→4 사이에 자동 경로는 없다. 그것이 C4 다.

## 4. 미해결 (사용자 결정 대기)

| # | 질문 | 왜 지금 못 정하나 |
|---|---|---|
| D1 | 표본 N 하한을 30 으로 할 것인가 | 검증 완료 정의(`COMPLETION_DEFINITION.md`)와 같은 30 을 쓸지, 고래 신호에는 다른 수를 쓸지 |
| D2 | 승률을 CI 하한으로 걸 것인가, 벤치마크 대비 우위로 걸 것인가 | 고래 신호의 대조군이 무엇인지 정해지지 않았다 — "고래 진입 직후 매수" 대 "무작위 시점 매수"의 비교 설계가 없다 |
| D3 | 지갑당·주기당 상한의 구체 수 | 발송 총량 예산이 정해진 적이 없다. 상한을 정하려면 "하루 몇 통까지 받을 것인가"가 먼저다 |
| D4 | 강등 유지 기간의 하한을 둘 것인가 | 조건만 통과하면 언제든 승격 가능하게 할지, 최소 관측 기간을 둘지 |
