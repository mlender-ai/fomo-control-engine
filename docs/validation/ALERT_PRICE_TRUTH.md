## 0. 실물 — 한 메시지 안에서 두 숫자가 모순이었다

```
🟢 MARSCOINUSDT 롱 10.0x — 익절1 도달                      (15:44)
익절1 0.136000에 도달했습니다. 현재 0.138190 · 목표 대비 +1.61%
건강도 60 · PnL -2.25% · 15:41 기준
```

| 읽는 값 | 함의 |
| --- | --- |
| 진입가 0.133510 · "현재 0.138190" | 진입 대비 **+3.5%** |
| PnL −2.25% · 레버리지 10x | 가격 **−0.225%** → 실제 마크 ≈ **0.13321** |

**둘 다 참일 수 없다.** 실제 마크는 0.1332 였고 익절1 0.136 에는 **닿은 적이 없다.**

## 1. 원인 — "현재"가 최대 4시간 묵은 종가였다

```python
# app/notify/rules.py  (수리 전)
def _current_price(payload):
    last_close = _last_close(payload)     # ← chart_analysis.candles[-1].close 를 최우선
    if last_close is not None:
        return last_close
    ...mark_price 계열은 그 다음...
```

그리고 그 캔들은 **확정봉만** 남는다:

```python
# app/exchange/bitget/provider.py:286
confirmed = [candle for candle in ... if candle.timestamp + timedelta(seconds=seconds) <= cutoff]
```

즉 `candles[-1].close` 는 **마지막으로 닫힌 4시간봉의 종가**이며 최대 4시간 묵은 값이다.
익절 도달 판정도, 본문의 "현재"도 그 값이었다. 반면 같은 메시지의 `PnL`·`기준 시각`은
`_snapshot_line(state)` 가 거래소 스냅샷에서 가져온다.

> **한 메시지가 두 시계를 썼고, 어느 쪽도 자기 출처를 밝히지 않았다.**
> 그래서 모순이 화면에 그대로 찍히고도 결함으로 보이지 않았다.

### 왜 묵은 종가를 우선했나 — 절반은 의도였다

무효화 이탈은 **"종가 이탈"이 규칙 자체다**(꼬리에 털리지 않으려는 설계이고 본문도
"종가 이탈했습니다"라고 적는다). 그 요구가 `_current_price` 하나에 뭉뚱그려지면서
**익절·근접까지 같은 출처를 쓰게 됐다.** 익절 도달은 정반대다 — 지금 행동해야 하는 알림이다.

## 2. 수리 — 규칙마다 맞는 시계를 쓰고, 값에 출처를 붙인다

```python
@dataclass(frozen=True)
class PriceReading:
    price: float
    source: str      # "mark" | "confirmed_close"
    as_of: Any
```

| 규칙 | 출처 | 근거 |
| --- | --- | --- |
| `take_profit_hit` | **현재가** | 지금 행동하라는 알림이다. 묵은 값이면 없는 기회를 보고 움직인다 |
| `trigger_near` | **현재가** | "얼마 남았다"의 거리는 지금 거리여야 한다 |
| `invalidation_breach` | **확정봉 종가** | 종가 이탈이 규칙이다 — 출처를 바꾸지 않는다 |
| `liq_cluster` | 확정봉 종가 | 관측이지 행동 지시가 아니다 |

세 가지를 함께 고정했다:

1. **현재가가 없으면 익절 도달을 판정하지 않는다.** 없는 것을 마지막 종가로 대신하는 것이
   이 결함의 시작이었다. 묵은 값으로 행동을 지시하느니 말하지 않는다.
2. **본문이 출처와 시각을 적는다** — `현재가 0.136500(15:44)` · `확정봉 종가 0.090000(12:00)`.
   맨 "현재 <숫자>"는 사라졌다.
3. **재무장을 발화와 같은 가격으로 잰다.** 익절을 현재가로 켜고 종가로 끄면 두 시계가
   엇갈려 알림이 반복되거나 영영 다시 켜지지 않는다.

## 3. "TP 가 짧다" — 짧은 것은 TP 가 아니라 손절이 멀었다

같은 포지션의 진입 알림:

```
다음 가격: 무효화 0.097105 (-27.10%) · 지금 볼 것: 0.136 저항 반응.
```

| | 거리 |
| --- | --- |
| 익절1 0.136000 | **+1.87%** |
| 무효화 0.097105 | **−27.10%** |
| **R:R** | **0.069** |

**1.87% 를 먹자고 27.10% 를 걸고 있었다.**

### 원인 — 구조 레벨 정렬이 점수 우선이다

```python
# app/structure/levels/engine.py:79
"support": sorted(support, key=lambda level: (-level.score, abs(mark - level.price)))[:8]
```

화면에 "어느 레벨이 중요한가"를 보여주기에는 맞는 순서다. 그런데 액션플랜이 그 목록의
**`[0]` 을 손절로 집었다**:

```python
# app/positions/chart_analysis.py  (수리 전)
strong_candidates = [level for level in candidates if level.score >= 40]
level = strong_candidates[0]          # ← "가장 강한 지지" = 손절?
```

"가장 강한 지지가 어디냐"와 "내 손절을 어디 두냐"는 **다른 질문이다.**

> 페이퍼 트랙에서 같은 결함을 이미 측정했다 — `NET_EDGE.md` §2-4 의 "무효화 거리 6~19 ATR".
> 이번 건은 그 진단이 **라이브에서도 맞다는 확인**이며, 구체적 숫자(27.10%)를 준다.

### 수리 — 가장 가까운 **유효** 레벨

`_select_invalidation_level` 로 분리했다. **점수 문턱(40)은 낮추지 않는다.** 그 문턱을
통과한 후보 중에서 노이즈 범위(0.8%)를 넘는 **가장 가까운** 것을 고른다.

| 상황 | 결과 |
| --- | --- |
| 유효 후보 여럿 | 가장 가까운 것 (`nearest_qualified`) |
| 전부 노이즈 범위 안 | **`insufficient_structure`** — 27% 짜리를 조용히 쓰지 않는다 |
| 점수 40 미만 | 후보가 아니다 (문턱 유지) |
| 기준가 없음 | 기존 동작(최고 점수)으로 되돌림 — 거리를 못 재면 고를 수 없다 |

고른 이유는 `selection`·`distance_pct` 로 남는다 — 사후에 "왜 손절이 저기냐"를 답할 수
있어야 한다.

## 4. 뒤집힌 계획은 조용히 나가지 않는다

손절 선택을 고쳐도 **계획이 뒤집혔을 때 말하지 않는 것**은 그 자체로 결함이다.
진입 알림에 한 줄을 추가했다 — 게이트가 아니라 문장이다.

```
⚠️ 손익비: 1.87% 목표 / 27.27% 위험 = R:R 0.07 — 거는 돈이 노리는 돈보다 큽니다.
   손절 위치를 먼저 확인하세요.
```

R:R ≥ 1 이면 경고 없이 사실만 적는다. 무효화나 목표가 없으면 **아무 말도 하지 않는다** —
비율을 지어내지 않는다.

## 5. 알림 수 — 이 수리가 줄이는 것

사용자 제보의 세 번째("포지션 잡았다 하면 알림이 나오고")는 앞 두 결함과 **같은 뿌리를
상당 부분 공유한다.**

- 거짓 "익절 도달"이 사라진다. 묵은 종가가 목표 위에 머무는 동안 그 알림은 목표마다
  하나씩(`익절1`·`익절2`…) 나갔고, 재무장도 같은 묵은 값으로 판정돼 상태가 굳었다.
- 근접 알림의 거리도 현재가로 다시 재므로, 실제로는 멀어졌는데 "곧 닿는다"고 말하던
  경우가 사라진다.

**남은 축(포지션당 알림 예산)은 이 수리가 실제로 몇 건을 줄이는지 본 뒤에 정한다.**
지금 상한을 씌우면 줄어든 것이 수리 때문인지 상한 때문인지 영영 가를 수 없고,
무효화 이탈 같은 진짜 위험 신호까지 함께 눌릴 위험이 있다.
