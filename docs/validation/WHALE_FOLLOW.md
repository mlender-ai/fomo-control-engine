# 고래 추종 트랙 (WO-FCE-WHALE-FOLLOW-01)

## 결론 먼저 — 트랙을 배선하지 않았다

WO §0 이 조건을 걸었다: 승격 통과자가 0명이면 5-3(페이퍼 트랙)·5-4(알림)를 착수하지 않는다.
빈 파이프를 만들지 않는다.

**2026-08-25 실측: 승격 통과자 0명.** 따라서 5-3·5-4 는 착수하지 않았다. 이 문서는 트랙
정의와 **결과를 보기 전에 고정한 게이트 범위**를 남긴다 — 나중에 결과를 보고 정하면 그것은
사후 합리화가 된다.

`test_follow_track_is_not_wired` 가 미배선 상태를 고정한다. 승격자가 나오면 그 테스트를
지우는 것이 5-3 착수의 첫 커밋이다.

## 왜 0명인가 — 사유는 확정됐다

WO 는 "0명이면 사유(CI 하한 미달인가, 표본 미달인가)를 확정하라"고 했다.

**표본 미달이 아니다. CI 하한 미달이다.**

| 지갑 | 채점 N | 승률 | CI 95% | 경과 | 달력 완주 | 유형 추정 |
| --- | --- | --- | --- | --- | --- | --- |
| `0x1ee7a7…edf5` | 39 | 51.3% | [**35.9**, 66.7] | 47일 | O | `directional` |
| `0x10f1d8…202f` | 37 | 64.9% | [**48.6**, 78.4] | 9일 | X | `unclassified` |
| `0x212abc…a8c6` | 34 | 50.0% | [**32.4**, 64.7] | 29일 | O | `unclassified` |

세 지갑 모두 N≥30 을 넘겼다. 표본은 도달했고 **승률이 못 넘었다.**

## 승격 기준의 실제 성격

기준은 28일 · N≥30 · CI 하한 55% 다(무변경, C5). 그런데 N≥30 과 CI 하한 55% 는 사실상
독립 조건이 아니다. 현행 승률을 유지할 때 CI 하한 55% 에 도달하는 데 필요한 표본:

| 승률 | 필요 N |
| --- | --- |
| 58.0% | 967 |
| 60.0% | 400 |
| 62.5% | 156 |
| 65.0% | 81 |
| 70.0% | 38 |
| 75.0% | 30 |

**"N≥30 이고 승률 55% 초과"가 아니라 사실상 "승률 62.5% 이상"이 실효 기준이다.** N=30 에서
통과하려면 승률 75% 가 필요하다. 이것은 기준을 낮추자는 제안이 아니다 — 기준이 실제로 무엇을
요구하는지 적어두는 것이다. 게이트를 세운 쪽이 이 표를 보고 판단할 수 있어야 한다.

개별 지갑에 적용하면:

| 지갑 | 승률 | 필요 N | 판단 |
| --- | --- | --- | --- |
| `0x10f1d8…202f` | 64.9% | **94** (추가 57건) | 9일에 37건 쌓았다 — 약 14일치. **28일 창 안에 도달 가능** |
| `0x1ee7a7…edf5` | 51.3% | N=1,500 까지 불가 | 승률이 임계선에 붙어 있다 |
| `0x212abc…a8c6` | 50.0% | N=1,500 까지 불가 | 같음 |

**단 한 지갑에 가능성이 있고, 그 지갑은 추적군에서 빠져 있었다.** 이것이 5-1 이 필요한 이유다.
회전이 계속되면 이 지갑은 N=37 에서 멈춘다. 고정하면 도달 여부가 2주 안에 결정된다.

단, 그 지갑은 `unclassified` 다(양방향 고빈도 — `WHALE_PARTICIPANT_TYPES.md`). **승격해도 추종
대상은 아니다.** 승격 심사와 추종 자격은 별개 관문이며, 지금 그 둘이 서로 다른 지갑을 가리킨다.

## 트랙 정의 (배선 시 적용 · 결과 전 고정)

### 진입 트리거

승격 고래(5-1) **이고** `directional` 추정(5-2)인 지갑의 **증액 체결**(`open`·`increase`·`flip`).
감액·청산(`reduce`·`close`)은 진입 신호가 아니다 — 별도 판단이다.

### 재사용 (신규 구현 0건, C2)

| 요소 | 출처 |
| --- | --- |
| 사이징 | `RISK-SIZING-01` Phase 1 리스크 기준 |
| 재진입 잠금 | 같은 봉 동일 방향 차단 (현행) |
| 출구 | 현행 사다리 — TP1 부분 · 본전 스톱 · TP2 |
| 손절 | 무효화선 |

### 무효화선

고래 체결에는 스톱이 없다. 구조 레벨에서 산출한다. **산출 불가면 진입하지 않는다** —
사이징이 스톱 거리를 요구하므로 무효화선 없는 진입은 사이징 불가와 같다.

### 적용 게이트 범위 — 결과 확인 전 고정

WO 5-3 항목 5 가 요구한 사전 고정이다. 아래 범위를 **채택**한다.

| 게이트 | 적용 | 근거 |
| --- | --- | --- |
| 데이터 신선도 | **유지** | 안전. 낡은 데이터로 진입하면 트랙 무관하게 잘못이다 |
| 청산 안전 | **유지** | 안전 |
| 유동성 | **유지** | 안전. 체결 불가 종목은 페이퍼에서도 무의미하다 |
| 일일 알림 한도 · 심볼 쿨다운 | **유지** | 발송·중복 통제 |
| `confirmed_flip` | **제외** | 고래 신호가 방향 판단을 대체한다는 것이 이 트랙의 가설이다 |
| `validated_signature` | **제외** | 같음 |
| `backtest_sample` · `backtest_win_1r_ci_low` | **제외** | 고래 트랙의 표본은 고래 트랙에서 쌓인다. 크립토 트랙 표본을 전제하면 순환이다(`DISCOVERY_GATE.md` 선례) |

방향 판단 게이트를 남기면 고래 신호의 기여를 측정할 수 없고, 안전 게이트를 빼면 품질 통제가
사라진다. 변수를 하나만 바꾼다.

### 원장 분리 (C1)

`paper_trades` 에 기입하지 않는다. 별도 원장을 쓰고 `TRACK_SAMPLE_SPECS` 에 `whale_follow` 로
등록한다. 트랙별 독립 판정이 `COMPLETION_DEFINITION.md` 규정이다. **미착수** — 승격자 0명.

### 지연 측정

고래 체결 시각 → 엔진 진입 시각. 이 지연이 추종 성과를 좌우한다. 트랙 배선 시 필수 실측
항목이며, 지금은 측정 대상이 존재하지 않는다(진입 0건).

## 5-5 실동작 증명 (2026-08-25)

WO 가 요구한 7항목. 착수하지 않은 항목은 추정치를 적지 않는다 — 없는 것은 0이다.

| # | 항목 | 실측 |
| --- | --- | --- |
| 1 | 승격 고래 수 | **0명** — 심사 대상 2개(N≥30 & 28일 완주), 통과 0. 사유는 CI 하한 미달 |
| 2 | 추종 대상 고래 수 | **15개**(전체 124지갑 중 `directional`). 현재 추적 20지갑 안에서는 **2개** |
| 3 | 진입 건수 · 체결→진입 지연 | **0건** — 트랙 미배선(§0). 지연은 측정 대상이 존재하지 않는다 |
| 4 | 청산 도달 | **0건** — 진입이 0이므로 표본도 0 |
| 5 | 텔레그램 발송 | **0건** — 알림 rule 미생성. 상한 동작은 배선 시 단위 테스트로 고정한다 |
| 6 | 크립토 트랙 무영향 · 잡 실행률 | `paper_trades` 60건(청산 56) 정상 진행 · 스케줄러 running · **굶은 잡 0/34** · 루프 지연 최대 0.685초(임계 5.0) |
| 7 | 24시간 관측 | **미완** — 세션 안에서 불가. 재기동 기준 시각 아래 참조 |

### 코호트 고정은 드라이런으로만 검증했다

옵트인 플래그가 **꺼져 있다.** `.env` 파일이 없어 서버는 기본값으로 돌고, 켜려면 재기동 시
환경변수를 줘야 한다. 라이브 설정 변경은 사용자 환경의 결정이므로 임의로 켜지 않았다.

라이브 데이터에 대한 드라이런(실제 레포 경로 · 읽기 전용):

```
whale_sample_sizes()  → 지갑 80개 · 표본 보유 53개 · 최대 N=39
cohort_plan()         → 유지 12 · 해제 8 · 복귀 8 · 신규 선발 슬롯 0
                        한도 준수 OK · 화이트리스트 밖 해제 사유 0건
복귀 상위 4            → N=39 · 37 · 34 · 19 (전원)
```

DB 확인: `whale_wallets` 에 `cohort_*` payload 기록 **0건** — 플래그가 꺼진 상태이고 새 코드
경로가 라이브에 개입하지 않았음을 확인한다.

### 켜는 방법과 켜지 않을 때의 비용

```bash
FCE_HYPERLIQUID_WHALE_COHORT_RETENTION_ENABLED=true python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8875
```

**켜지 않으면 `0x10f1d8…202f` 는 다음 발견 실행에서 추적군에서 빠지고 N=37 에서 멈춘다.**
그 지갑이 승격 가능성이 있는 유일한 후보이며(N=94 도달까지 약 14일), 회전이 계속되면 그
가능성은 측정되지 못한 채 사라진다. 되돌리는 것은 플래그를 끄고 재기동하는 것뿐이다.

### 미완 항목

- **24시간 관측** — 재기동 기준 2026-08-25 (`/api/onchain/whales` 200 · 2.39초, 종전 6.95초).
  확인할 것: 굶은 잡 0 유지 · 코호트 계획이 매 발견 실행에서 동일 결론을 내는지(안정성)
- **`0x10f1d8…202f` 의 N=94 도달 여부** — 코호트 고정이 켜진 뒤 약 2주. 이 WO 전체의 결과를
  정하는 단일 관측이다
- **MM 오염 표본 처리** — `0x362ad620`(maker 98.8%)이 표본 11건을 쌓았다. 그 표본을 승격
  심사에서 제외할지, 유형 추정을 소급 적용할지는 이 WO 의 범위가 아니다. 판정 원장 소급
  변경은 별도 결정이 필요하다
