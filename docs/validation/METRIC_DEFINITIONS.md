# 지표 정의 (Metric Definitions)

> WO-FCE-METRIC-TRUTH-01 정본. **수익률·창 술어·모집단의 단일 기준.**
> 여기서 벗어난 계산이 화면이나 리포트에 나타나면 그것이 결함이다.

---

## 0. 왜 이 문서가 생겼나 — 두 오류가 서로를 가리고 있었다

### 오류 1 — 퍼센트 단순합

```python
paper/service.py   "net_return_pct": round(sum(returns), 4)   # 옛 정본
```

거래별 수익률(%)을 **사이즈 무시하고 그냥 더했다.** 복리도 자본 가중도 아니다.

사용자 진입 명목이 **11 ~ 3,021 USDT (267배 편차)** 인데 퍼센트를 더하면, 작은 포지션의
큰 %수익이 큰 포지션의 %손실을 상쇄한다.

### 오류 2 — 창 술어 비대칭

```
엔진   paper/service.py:682        entry_at >= 앵커
사용자 db/repository/paper.py:51   exit_at  >= 앵커
```

같은 앵커인데 다른 집합을 잘랐다. 사용자 쪽에만 **앵커 이전 로직으로 진입한 거래**가 섞였다.

### 둘을 함께 고쳐야 했다

| 정의 | 사용자 성적 |
| --- | --- |
| 구: `exit_at` + 퍼센트합 | **+17.57%** (화면) / 실제 −261.85 USDT |
| `entry_at` + 퍼센트합 | +36.18% |
| **신: 양쪽 술어 + 금액** | **+151.85 USDT** |

**한쪽만 고쳤으면 여전히 틀린 숫자를 봤을 것이다.** 술어 오염이 금액을 음수로 만들었고,
퍼센트 합산이 그것을 양수 %로 뒤집고 있었다.

## 1. 수익률 정의 (결정 1)

**퍼센트 단순합은 성과 지표가 아니다.** 두 값을 함께 낸다.

| 지표 | 정의 | 비고 |
| --- | --- | --- |
| `net_pnl_usdt` | `sum(net_pnl_usdt)` | **대표값.** 가감 없는 사실 |
| `return_on_capital_pct` | 금액 ÷ 운용 자본 × 100 | 자본 미상이면 **`None`** |
| `capital_usdt` · `capital_note` | 자본과 그 근거 | 근거 없는 자본은 쓰지 않는다 |
| `legacy_return_sum_pct` | 옛 퍼센트 합 | **강등 보존**(C4). 대표 자리에서만 내렸다 |

### 운용 자본

- **엔진** = `margin_usdt × max_open_positions` (현재 100 × 5 = **500 USDT**).
  하드코딩하지 않는다 — 설정이 바뀌면 자본도 바뀐다.
- **사용자** = **미산출**. 계좌 잔고 테이블이 없고 `user_trades` payload 에 레버리지가 없어
  명목에서 증거금을 역산할 수 없다. **추정치로 채우지 않는다**(C5) — 채우는 순간 이 WO 가
  고치려는 오류를 다시 만드는 것이다.

### 낙폭도 금액이다

낙폭을 퍼센트 곡선에서 재면 사이즈가 다를 때 의미가 흐려진다. `mdd_usdt` 가 대표이고
자본이 있으면 `mdd_pct` 를 함께 낸다. 자산 곡선(`equity_curve`)도 금액 기준으로 바꿨다 —
낙폭은 금액인데 곡선만 퍼센트면 둘이 어긋난다.

## 2. 창 술어 (결정 2)

```
entry_at >= 앵커  AND  exit_at IS NOT NULL  AND  exit_at <= 종료
```

**둘 중 하나를 고르는 문제가 아니다.**

- `entry_at` 만: 결과가 창 밖에서 난 거래가 들어온다
- `exit_at` 만: 앵커 이전 로직으로 진입한 거래가 들어온다

양쪽을 걸면 **"창 안에서 결정하고 창 안에서 결판난"** 것만 남는다.
청산되지 않은 거래는 결판이 나지 않았으므로 성과 모집단에 들어가지 않는다.

정본: `app/paper/window.py`. **엔진과 사용자가 같은 함수를 호출한다** —
두 곳에 각각 구현하면 다시 갈라진다(실제로 그래서 갈라졌다).

---

## 3. 모집단 (결정 3)

**청산 완료 전량이 단일 모집단이다.** 승률·손익비·PF·수익률·낙폭이 **같은 집합** 위에서 계산된다.

이전에는 승률을 채점군(19건), 수익률을 전체(29건) 위에서 쟀다. 그 분리가
`EXPECTANCY-01` 의 "실현 손익비 0.42" 오류의 직접 원인이었다 — 서로 다른 모집단의
두 값을 곱해 유도한 값이었기 때문이다.

`time_decay` · `time_stop` 은 **계수에서 빼지 않는다.** 실제로 발생한 결과다.
실측에서 제외되던 `time_decay` 10건은 합계 **+6.73%(양수)** 였다 — 빠지는 것이 손실이 아니라
**이익**이었다. 결과를 범주 이름으로 지우면 안 된다.

`neutral_count` 는 **관측 정보로 계속 표시**한다. 분모에서만 빼지 않는다.

## 4. 우열 판정 (결정 4)

**"엔진이 사용자를 이긴다"는 현재 판정하지 않는다.** `engine_leading = None` 이 정상값이다.

자본 기준이 다르다. 엔진은 500 USDT 가 확정돼 있고 사용자 자본은 미산출이다.
**자본이 다른 두 계열의 절대 금액을 비교하면 규모가 큰 쪽이 자동으로 유리**해지고,
그것은 실력 비교가 아니다.

`LIVE_TRADING_GATE.md` 축 2 는 `미판정` 으로 유지한다. **절대 기준(PF > 1 · 기대값 > 0)이
선행 조건**이며, 사용자 자본이 확보되면 그때 자본 대비 수익률로 비교한다.

## 5. 신 정의 기준 실측 (2026-08-16 · 앵커 2026-07-17)

| 항목 | 엔진 | 나 |
| --- | --- | --- |
| **손익 (USDT)** | **−46.84** | **+151.85** |
| 운용 자본 | 500 | 미산출 |
| 자본 대비 | −9.37% | 미산출 |
| 승률 | 51.72% | 66.67% |
| 수익팩터 | 0.5763 | 1.8744 |
| 최대 낙폭 (USDT) | 81.61 | 59.36 |
| N (중립) | 29 (10) | 54 (0) |

### 구/신 대조

| | 구 정의 | 신 정의 |
| --- | --- | --- |
| 엔진 | −46.84% (퍼센트합) | **−46.84 USDT (−9.37%)** |
| 나 | **+17.57%** (`exit_at`·퍼센트합) | **+151.85 USDT** |

**엔진 수치는 우연히 같다** — 고정 사이즈(증거금 100)라 퍼센트 합과 금액이 1:1로 대응한다.
그러나 **자본 대비로 보면 −46.84%가 아니라 −9.37%다.** 낙폭도 "81.61%"가 아니라
81.61 USDT(자본 대비 16.3%)다. **구 정의는 엔진 손실을 5배 과장하고 있었다.**

사용자는 구 정의가 성적을 **양수 %로 표시하면서 실제 금액은 음수**로 만들고 있었는데,
술어까지 고치니 **실제로는 창 안에서 벌었다**.

## 6. 금지

- 퍼센트 단순합을 성과 대표 지표로 사용
- 엔진과 사용자에 다른 창 술어 적용
- 승률과 수익률을 다른 모집단에서 계산
- 특정 `exit_reason` 을 계수에서 제외
- 사용자 운용 자본을 추정치로 기입
- 자본 기준이 다른 계열의 절대 금액으로 우열 판정
- `legacy_return_sum_pct` 삭제 — 연속성이 끊기면 이런 오류를 다시 못 찾는다
