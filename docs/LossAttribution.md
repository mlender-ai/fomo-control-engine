# 손실 패인 분류 (Loss Attribution)

> **패인 분포는 관측이며 파라미터 자동 변경 입력이 아니다.**
> 분포를 근거로 임계값을 바꾸는 것은 별도 WO에서 **한 번에 하나씩** 검증한다.
> `app/review/loss_attribution.py` 는 분류만 하고 어떤 게이트·임계도 건드리지 않는다.

judgment ledger 는 T+1/T+5/T+20 결과를 채점하지만 **왜 졌는지**는 분류하지 않았다.
"졌다"는 알아도 패인을 모르면 개선 입력이 되지 않는다. 이 문서가 그 분류 체계를 고정한다.

신규 집계 테이블은 만들지 않는다 — 태그는 기존 원장(`paper_trades.loss_tags`)에 싣는다.

## 분류 6종

| 태그 | 뜻 | 판정 규칙 |
| --- | --- | --- |
| `gap_loss` | 갭으로 무효화선보다 나쁘게 체결 | `exit_reason == "gap_loss"` 또는 체결이 갭 판정됨 |
| `time_stop` | 시간 손절 — 방향은 틀리지 않았으나 진행 없음 | `exit_reason ∈ {time_stop, time_decay}` |
| `entry_too_late` | 진입 후 즉시 역행 — 구조상 늦은 진입 | 보유 봉 수 ≤ 1 |
| `invalidation_too_tight` | 무효화 직후 원래 방향 복귀 — 손절이 좁음 | 청산 후 원방향 되돌림 ≥ 0.5R |
| `structure_misread` | 진입 시 판정한 국면이 사후 재해석됨 | 진입 stance ≠ 청산 stance |
| `invalidation_correct` | 무효화선이 옳았고 시장이 반대로 감 (불가피) | 위 어디에도 해당 없음 |

판정 순서가 곧 우선순위다. **갭이 최우선**인 이유: 체결 자체가 무효화선보다 나빴다는
사실이 다른 어떤 해석보다 먼저다.

### 모르는 것은 단정하지 않는다

`invalidation_too_tight` 판정에는 **청산 이후 원방향 최대 도달가**(`post_exit_extreme`)가
필요하다. 그 관측이 없으면 "좁은 손절"이라고 단정하지 않고 `invalidation_correct` 로
남긴다 — 되돌림을 못 봤다는 것과 되돌림이 없었다는 것은 다르다.

되돌림 임계 0.5R 은 **관측용 판정 기준이며 어떤 진입 게이트에도 쓰이지 않는다.**

## 주간 자체평가 리포트 규격

```
🔎 손실 자체평가
· 손실 6건 분류
· 손절이 너무 좁음 (직후 복귀) 4건 (67%)
· 시간 손절 (방향은 유지, 진행 없음) 1건 (17%)
· 갭 손실 (무효화선보다 나쁘게 체결) 1건 (17%)
→ 손절폭 재검토 후보 (자동 적용 아님 — 별도 WO에서 단건 검증)
패인 분포는 관측이며 파라미터 자동 변경 입력이 아닙니다.
```

- 표본 0이면 "분류 대상 손실 없음" 만 쓰고 **숫자를 만들지 않는다**(3트랙 공통 표본 규칙).
- 개선 제안은 항상 **후보**로만 적는다. 자동 적용 금지 원칙을 리포트 문장에도 남긴다.

## 트랙별 적용 현황 (2026-08-03)

| 트랙 | 청산 표본 | 태깅 |
| --- | --- | --- |
| 크립토 | 12건(비거래 2건 제외) | 적용 대상 |
| 주식 KR·US | **0건** | 청산 엔진이 첫 청산을 만든 뒤부터 |
| 폴리 | 0건 (정산 대기) | 만기 도래 후 |

주식은 청산 경로 자체가 없었으므로 분류할 대상이 없었다. 청산 엔진 정본은
**WO-FCE-STOCK-EXIT-01**(`app/stock_paper/exit_policy.py`)이며, 그 엔진의 첫 청산부터
태깅된다.

정본 청산 엔진은 **판단과 체결을 분리**한다 — `exit_policy` 는 "청산할 것인가/얼마나"만
정하고 체결 가격은 `execution.py` 가 관측 데이터에서 파생한다. 그래서 무효화선 100에서
이탈해도 100에 체결되지 않고 장외 이탈이면 다음 세션 시가에 체결된다. `gap_loss` 태그는
그 실제 체결 결과를 분류하는 것이지 별도 체결 규칙을 만드는 것이 아니다.
