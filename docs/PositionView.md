# 라이브 포지션 화면 표시 규칙 (Position View)

> WO-FCE-POSITION-VIEW-01 정본. **표시 계층 전용.** 국면 판정·방향 로직은 건드리지 않는다
> (`analyst/` · `structure/` diff 0줄) — 판정 수리는 `DIRECTIONAL-INTEGRITY` 소관이다.
>
> 이 화면은 사용자가 **실계좌 판단에 쓴다.** 표시 오류가 곧 매매 오류가 된다.

---

## 0. 표시 3원칙

1. **단위를 섞지 않는다.** 가격 라벨 자리에는 가격을 쓴다. 다른 축의 값을 `$` 붙여 놓지 않는다.
2. **근거 없는 주장을 확신 문형으로 쓰지 않는다.** 표본이 없으면 `현재 판정:` 이고 `…입니다` 가 아니다.
3. **모순을 감추지 않는다.** 상충하는 지표는 상충한다고 적는다. 한쪽을 지워 정합을 만들지 않는다.

## 1. D1 — 밀집 라벨이 가격이 아니었다 (표시 결함)

**판정: 선 위치는 맞고 라벨 값이 틀렸다.**

```
components/position/PositionCandlestickChart.tsx:1343-1344
  const y1 = series.priceToCoordinate(zone.price_high);   ← 가격 기반. 정확하다
  const y2 = series.priceToCoordinate(zone.price_low);

같은 파일 (수정 전)
  const label = `밀집 ${index+1} · ${formatUsd(zone.total_usd_estimated)}`;   ← 거래대금이다
```

`total_usd_estimated` 는 **청산 밀집대의 추정 거래대금**이다. 그것을 `$` 붙여 **가격 밴드**
라벨로 썼다. 실측 2026-08-16: 차트 가격축 100~320 인데 `밀집 1 · $570.64` 가 떴고,
570.64 는 우하단 볼륨 프로파일 스케일 상한과 **같은 값**이었다.

사용자는 이 선을 지지·저항 **가격**으로 읽는다. 570.64 는 가격이 아니다.

**수정**: 라벨을 가격 범위로 바꾸고 규모는 단위를 명시해 병기한다. 목록 카드의 `<small>`
도 가격 바로 아래에 있어 또 다른 가격으로 읽히므로 `규모` 를 붙인다.

화면 실측 (2026-08-18 · 데모 스택 · 밀집대 주입):

```
차트 밴드 라벨   밀집 1 · 3,900~3,950 · 규모 $570.64      ← 밴드가 실제로 3,900~3,950 에 그려짐
목록 카드        밀집 1 / 3,925 / 규모 $570.64 · 12건
```

수정 전이라면 같은 화면에서 `밀집 1 · $570.64` 가 3,925 위치에 떴다 — **6.9배 어긋난 값**이다.

## 2. D2 — `−51.69%` 는 계산 오류가 아니었다 (근거 미표시)

**산출식** (`app/positions/pnl.py`):

```python
# exchange 경로 (우선)
pnl_percent = (unrealized_pl / margin_size) * 100

# computed 경로
pnl_percent = ((entry − mark) / entry) * 100 * leverage     # short
              ((mark − entry) / entry) * 100 * leverage     # long
```

**ROE(증거금 대비 수익률)이고 레버리지가 곱해져 있다.**

실측 검산 (NBISUSDT · `pnl_source=computed`):

```
short · 진입 270.25 · 표시가 275.88 · 20배
(270.25 − 275.88) / 270.25 × 100 × 20 = −41.67%     ← 화면값과 정확히 일치
```

**계산은 옳았다.** 문제는 화면에 **방향·레버리지가 없어서 사용자가 검산할 수 없었던 것**이다.
진입가 270.25 와 현재가 277.52 만 보면 +2.7% 인데 −51.69% 가 떠 있으니 오류로 읽힌다.

`WO-FCE-METRIC-TRUTH-01` 의 퍼센트 결함과는 **다른 원인**이다 — 그쪽은 사이즈 무시 합산이었고,
이쪽은 정상적인 ROE 인데 근거가 안 보였다. 상호 참조:
[`validation/METRIC_DEFINITIONS.md`](validation/METRIC_DEFINITIONS.md).

**수정**: 손익률에 근거를 항상 병기한다.

```
−41.67% · 숏 20배 · 교차 · 가격 기준 ROE · 증거금 대비
```

차트 헤더에도 방향·레버리지·표시가를 같은 줄에 둔다.

### ⚠️ 1차 수정이 렌더되지 않는 곳에 들어갔다 (자기 정정)

근거 라벨을 처음에는 `minimalPnlSecondary()` 에 넣었다. 그 함수의 유일한 호출자는
`MinimalPositionVerdictCard` 인데 **그 컴포넌트를 어디에서도 참조하지 않는다.**

```
프로덕션 번들 문자열 검사
  positionOneQuestion   → 0건      ← 사문(死文) 컴포넌트
  증거금 대비            → 0건      ← 수정이 화면에 도달하지 않았다
```

**타입체크·린트·빌드는 전부 통과했다.** 죽은 코드를 고쳐도 게이트는 녹색이다.
번들 문자열 검사와 화면 실측을 하지 않았다면 "수정 완료"로 보고했을 것이다.

실제 렌더 경로는 `PositionVerdictBar`(`data-testid="verdict-bar"`)와 포지션 스트립이다.
거기로 옮긴 뒤 화면 실측 (2026-08-18 · 데모 스택):

```
ETHUSDT 숏 10x
−179.41%  숏 10배 · 가격 기준 ROE · 증거금 대비   [ROE · -100% 초과 가능]
```

> ⚠️ `exchange` 경로일 때는 수수료·펀딩이 포함되므로 **진입가·현재가·레버리지만으로는
> 검산되지 않는다.** 그 경우 `거래소 미실현 기준(수수료·펀딩 포함)` 으로 출처를 밝힌다.

## 3. D7 — 라벨 병합이 가격을 버렸다

`stackFlags` 는 12px 이내로 가까운 플래그를 병합하면서 **이름만 이어 붙이고 가격을 지웠다**
(`익절2·익절1`). 겹쳤다는 사실보다 **그 선이 어느 가격인지**가 필요한 정보다.

**수정**: 병합 시 가격 범위를 유지한다 — `익절1·2 275.40~276.10`.

### 가격을 남기려면 폭이 아니라 줄을 늘려야 한다

이름+가격범위를 한 줄에 넣으니 두 곳에서 다시 가격이 사라졌다.

1. `truncateSvgLabel(label, 15)` 가 **가격 쪽을 잘라냈다**
2. 예산을 26자·182px 로 늘리자 우측 거터(고정 폭)를 넘어 **화면 밖으로 잘렸다** — 실측 확인

거터 폭은 늘릴 수 없으므로 **두 줄로 쪼갠다.** 이름이 길면 이름을 자르고, **가격은 자르지 않는다.**
병합 플래그는 30px 높이가 되므로 스택 간격도 26 → 34px 로 넓힌다.

화면 실측 (2026-08-18 · 익절 2개를 무효화가 부근으로 주입해 충돌 재현):

```
SVG 플래그 텍스트
  ["내 진입 3,400", "현재 4,009.99", "익절2·익절1·무효화", "3,650~3,670"]
                                     └─ 1줄: 무엇이 겹쳤는지  └─ 2줄: 어느 가격인지
```

## 4. D3·D4 — 근거 강도와 상충을 라벨에 붙인다

실측: `분산 Phase E · 레인지 197.1–284.2 · 실제 확인 이벤트 0건 · 상승 추세`

두 모순이 한 줄에 있었다.

- **이벤트 0건인데 국면이 `confirmed` 스타일로 확정 표시** (D3)
- **`분산 Phase E`(마크다운=하락 구간) + `상승 추세` 동시 표기** (D4) — 정석상 공존 불가

화면은 두 사실을 숨기지 않고 나란히 보여줬지만 **그것이 모순이라는 표시가 없었다.**

**수정** (표시만 · 판정 무변경):

```
분산 Phase E · 미확증
레인지 197.10–284.20
확인 이벤트 0건 · 상승 추세 — 이벤트 0건이므로 판정 근거가 없습니다
⚠️ 국면과 추세가 상충합니다 (분산 국면 + 상승 추세) — 어느 쪽이 맞는지는 판정하지 않습니다
```

`phaseTrendConflict()` 가 상충을 판정한다. **어느 쪽이 맞다고 정하지 않는다**(C4).
국면 판정 수리(선행 추세가 판정에 안 들어감)는 `DIRECTIONAL-INTEGRITY` D1 소관이다.

상충 경고는 **한 행을 다 쓴다**(`grid-column: 1 / -1`). 같은 행에 두면 `.taLayerStatus` 그리드의
`1fr` 칸이 눌려 옆 근거 문장이 어절 중간에서 찢어졌다(`상 / 승 추세`) — 실측으로 확인했다.

화면 실측 (2026-08-18):

```
강제 주입 (이벤트 0건 + distribution + 상승)
  distribution e · 미확증   레인지 3,671.17–4,055.82   확인 이벤트 0건 · 상승 추세 — 이벤트 0건이므로 판정 근거가 없습니다
  ⚠️ 국면과 추세가 상충합니다 (분산 국면 + 상승 추세) — 어느 쪽이 맞는지는 판정하지 않습니다

주입 없는 실데이터 (BTC · 4h)
  분산 Phase C   레인지 99,586.07–110,287.84   확인 이벤트 1건 · 상승 추세
  ⚠️ 국면과 추세가 상충합니다 (분산 국면 + 상승 추세) — 어느 쪽이 맞는지는 판정하지 않습니다
```

> 두 번째는 **주입 없이 실제로 발생했다.** 상충이 드문 예외가 아니라는 뜻이다.
> 발생률은 여전히 산출 불가(§7) — 국면이 저장되지 않는다.

## 5. D5 — 확신 문형을 근거 강도에 맞춘다

| 이전 | 현재 |
| --- | --- |
| `현재 국면은 분산 Phase E입니다.` | `현재 판정: 분산 Phase E` |
| `최다 거래 가격은 …입니다.` | `최다 거래 가격: …` |
| `거래량 상태는 …입니다.` | `거래량 상태: …` |

같은 화면에 `이 레이어의 검증 표본을 축적 중입니다`(N=0) 가 있는데 판정은 단정형이었다.
**단정형은 표본이 있을 때만 쓴다**(C3).

화면 실측 (2026-08-18 · 스카우트 → BTC → 프로 → 와이코프 포커스):

```
현재 주장       현재 판정: 분산 Phase C
백테스트 성적   이 레이어의 검증 표본을 축적 중입니다.
최근 판단 이력   이 심볼의 채점 가능한 판단 이력이 아직 없습니다.
```

남은 `…입니다` 두 개는 **판정이 아니라 시스템 자신의 상태**를 말하는 문장이므로 그대로 둔다.
단정형 금지는 근거 없는 **판정**에 걸리는 규칙이다.

## 6. D6 — 판단 이력의 상충을 표시한다

실측: 같은 날 `sweep confirms down` 1건 · `sweep confirms up` 2건이 전부 `채점 대기` 로
나란히 있었다. 상충 표시도, 어느 것이 유효한지도 없었다.

**수정**:

- 상반된 방향이 공존하면 `⚠️ 같은 기간에 상반된 판단이 함께 있습니다 (상승 2건 · 하락 1건)`
- **어느 쪽이 맞다고 판단하지 않는다**(C4)
- 시각을 **분 단위**로 — 날짜만 있으면 상충인지 순서인지 구분되지 않는다
- 채점 대기에 사유를 붙인다: `채점 대기 · 전방 관측 창 미도래`

### 화면 실측을 못 했다 (C8)

D6 만 **화면에서 확인하지 못했다.** 데모 스택에 판단 이력이 없어
`이 심볼의 채점 가능한 판단 이력이 아직 없습니다.` 만 뜬다 — 상충 표시가 걸릴 데이터 자체가 없다.

코드 경로는 있으나 **렌더 증거가 없다.** D2 에서 게이트가 녹색인데도 수정이 화면에 없었던 일이
있었으므로(§2) 이 항목은 **미검증으로 남긴다.** 실계 판단 이력이 쌓인 심볼에서 재확인해야 한다.

## 7. 미산출 — 발생률 (C2 정직성)

**이벤트 0건 확정 국면의 발생률**과 **국면-추세 상충 발생률**은 **산출하지 못했다.**

사유: **와이코프 국면(phase)이 어디에도 저장되지 않는다.** 요청 시점에 계산되고 버려진다.

```
market_snapshots.payload      → wyckoff_phase 없음 (indicators·scores·reason_codes 만)
judgment_ledger               → wyckoff_event 15,585건은 있으나 phase 없음
paper_gate_funnel             → 없음
stance_history_candles        → 없음
position_snapshots            → 없음
```

**국면 판정이 저장되지 않아 사후 검증이 원리적으로 불가능하다.** 이것 자체가 발견이며
`DIRECTIONAL-INTEGRITY` 로 이관한다 — 판정을 검증하려면 먼저 판정을 기록해야 한다.

추정치를 만들지 않았다.

## 10. 검증 방법 — 게이트만으로는 부족하다

이 WO 에서 **타입체크·린트·테스트·빌드 전부 녹색인데 수정이 화면에 없었다**(§2).
표시 계층 수정은 다음 셋을 다 통과해야 완료다.

| 단계 | 무엇을 잡는가 |
| --- | --- |
| 1. 게이트 | 문법·타입·회귀 |
| 2. 번들 문자열 검사 | 죽은 코드에 넣은 수정 (`grep -rl "새 문구" .next`) |
| 3. 화면 실측 | 잘림·겹침·줄바꿈 — 문자열이 있어도 **읽을 수 없는** 경우 |

3단계에서만 잡힌 것: 병합 라벨의 화면 밖 잘림, `증거 / 금 대비` 어절 중간 줄바꿈,
`.taLayerStatus` 행 압착으로 인한 문장 찢김. 어느 것도 게이트에 걸리지 않는다.

조건부 표시는 **조건을 주입해서** 봐야 한다 — 데모 데이터로는 D3·D4·D7 이 한 번도 렌더되지 않았다.

## 9. 금지

- 가격 라벨 자리에 다른 축의 값 표시
- 출처 확정 없이 그럴듯한 값으로 교체
- 표본 없는 판정의 단정형 표시
- 상충 지표 중 한쪽을 숨겨 정합을 만드는 것
- 라벨 병합 시 가격 정보 폐기
- 손익률을 근거(방향·레버리지·출처) 없이 단독 표시
