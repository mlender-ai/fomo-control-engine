# 주식 페이퍼 청산 정책

WO-FCE-STOCK-EXIT-01 정본.

> **가장 중요한 규칙: 무효화 가격에 마법 체결하지 않는다.**
> 무효화선이 장외에 이탈되면 **다음 세션 시가**로 체결한다. 무효화 가격에 체결시키면 손절이
> 실제보다 좋아 보이고, 그 성적으로 자동매매를 판단하면 실거래에서 그대로 손실이 된다.

## 무엇이 없었나

이 WO 이전에 주식 페이퍼는 **매도 주문을 생성하는 코드가 전 코드베이스에 없었다.**

| 위치 | 성격 |
|---|---|
| `accounting.py:25` | 매도**라면** 거래세를 계산하겠다 |
| `execution.py:43` | 매도**라면** 하한가 잠김을 확인하겠다 |
| `broker.py:43` | 매도**라면** 보유 수량을 검증하겠다 |

셋 다 **오지 않는 매도를 기다리는 처리기**였다. `service.py`의 `StockOrder` 생성은 `side=Side.BUY` 한 곳뿐이었고, 무효화선을 계산해 진입 게이트에 쓰면서도 그 선에 도달했을 때 아무 일도 일어나지 않았다.

결과: 청산 0건 → 승률 "표본 없음" → 4주 검증 성립 불가 → 어떤 진입 개선도 효과 측정 불가.

## 판단과 체결의 분리 (핵심 계약)

| 책임 | 모듈 | 결정하는 것 |
|---|---|---|
| **판단** | `exit_policy.py::evaluate_stock_exit` | 청산할 것인가 / 잔여의 몇 %를 |
| **체결** | `execution.py::execute_order` | **가격·수량·수수료·세금** (관측 데이터에서만 파생) |

`evaluate_stock_exit`은 **가격을 절대 반환하지 않는다.** `StockOrder.signal_price`는 기록용이며 체결가로 쓰이지 않는다. 이 분리가 갭 정직성을 구조적으로 보장한다 — 마법 체결을 하려면 아키텍처를 어겨야 한다.

## 청산 트리거 (우선순위 순, 위쪽이 이김)

| # | 트리거 | 조건 | 청산 비율 |
|---|---|---|---|
| 1 | `forced_liquidation` | 거래정지·정리매매·상장폐지·관리종목 경고 | 전량 (미체결 시 사유 기록) |
| 2 | `invalidation_breach` | **종가** ≤ 무효화선 (TP1 실현 후엔 max(무효화선, 평단)) | 전량 |
| 3 | `take_profit` | 종가 ≥ 해당 단계 목표가 | 사다리 배분 (40/35/25) |
| 4 | `time_stop` | 보유일 ≥ `max_holding_days` | 전량 |

- **종가 기준**(`invalidation_basis: "close"`)만 허용한다. 장중 터치로 판정하면 꼬리에 스쳐도 손절되어 성적이 실제보다 나빠지고, 무엇보다 확정되지 않은 값으로 판단하게 된다. 파라미터 로더가 다른 값을 거부한다.
- **강제 청산이 이익 목표보다 앞선다.** 목표가에 도달했어도 거래정지면 나가는 것이 먼저다.
- **TP 사다리는 순서대로 오른다.** 아래 단계가 미달이면 위 단계도 보지 않는다. 실현한 단계는 `realized_levels`에 기록되어 반복 체결되지 않는다.
- **TP1 실현 후 본전 이동**(`breakeven_stop_after_tp1`): 잔여분의 손절선을 `max(무효화선, 평단)`으로 올린다.

### 시간 손절 기본값 근거 — `max_holding_days: 10`

10 거래일(약 2주)로 정한 이유:

1. **직접적 사건**: 07-22·23 진입분이 청산 경로 부재로 **8일간 방치**되며 미실현 −25.53%(KR)까지 갔다. 시간 손절은 그 재발을 막는 안전판이다.
2. **분석 시간축과 정합**: 진입 판단은 일봉(`timeframe="1d"`) 기준이며, 무효화선·목표는 일봉 구조 레벨에서 나온다. 10 거래일은 그 구조가 유효한지 판정되기에 충분하고, 무한 보유로 자본을 묶지 않는 길이다.
3. **검증 표본 축적 속도**: 4주(28일) 검증 창에서 상한 10일이면 포지션이 최소 2회전하므로 표본이 쌓인다. 무기한 보유는 검증 시계를 왜곡한다.
4. 값은 파라미터이며 근거가 쌓이면 조정한다. **단, 한 번에 하나씩 검증한다**(AGENTS.md).

## 체결 정직성 (진입 규칙과 대칭)

| # | 규칙 | 동작 |
|---|---|---|
| 1 | 세션 게이트 | 정규장에서만 체결. 장외 신호는 `session_closed`로 대기 → 다음 개장 처리 |
| 2 | **갭 체결** | 대기 주문은 **다음 세션 시가**(`session_open_price`)로 체결. 무효화 가격 체결 금지 |
| 3 | 하한가 잠김 | KR 하한가 잠김 시 매도 미체결 → 대기 + `price_limit_locked` 기록 |
| 4 | VI·거래정지 | 체결 불가 → 대기 + 사유 기록. 강제 청산도 시도만 하고 **미체결 사유를 남긴다** |
| 5 | 유동성 상한 | 직전 1분 거래량의 5% 초과 시 **부분 체결**, 잔량은 다음 틱 재시도 |
| 6 | 거래세·수수료 | KR 매도 시 증권거래세 반영(매수엔 없음), 수수료 양방향 |
| 7 | 체결가 invariant | 체결가가 관측 봉 범위 밖이면 `FillInvariantViolation` → 트랙 정지 + 경고 |

핵심 구현 지점 — `execution.py:53`:
```python
base = observation.session_open_price if order.reason == "session_closed" else observation.minute_close
```
장외 대기 주문은 다음 세션 **시가**를 기준가로 쓴다. 체결가는 언제나 관측에서 파생되며 신호가에서 오지 않는다.

**회귀 가드**: `tests/test_stock_exit.py::test_gap_exit_fills_at_next_session_open_not_invalidation_price` — 무효화선 100, 다음 시가 92 → **92 체결** 검증. 이 테스트가 이 문서의 심장이다.

## 파라미터 (`params/stock-exit-v1.json`)

| 키 | 기본값 | 의미 |
|---|---|---|
| `invalidation_basis` | `close` | 무효화 판정 기준(종가만 허용) |
| `max_holding_days` | 10 | 시간 손절 상한(거래일) |
| `tp_ladder` | 40/35/25 | 분할 청산 배분(합 1.0 강제) |
| `breakeven_stop_after_tp1` | true | TP1 실현 후 본전 이동 |
| `forced_exit_warnings` | 거래정지·정리매매·상장폐지·관리종목지정 | 강제 청산 트리거 |
| `max_carryover_days` | 3 | 미체결 청산 주문 이월 상한 |

진입 파라미터(`stock-v4.json`)는 **수정하지 않았다**(C2). 청산은 별도 파일이다.

## 고아 포지션 처리 (C4)

07-22·23 진입 6건은 청산 경로 부재 구간의 산물이다. **8일 보유는 엔진의 판단이 아니라 코드 부재의 결과**이므로 어떤 방식으로 청산하든 그 손익은 엔진 성과가 아니다.

- `excluded_from_stats=1`, `exclusion_reason='void_no_exit_path'`로 표식한다. 승률·평균 R·검증 표본에서 제외하되 **원장 행은 그대로 남는다**.
- 판별 기준: `exit_plan`에 무효화선이 없는 보유분(새 진입은 체결 시 plan이 박힌다).
- 도구: `scripts/void_orphan_stock_positions.py` (기본 dry-run, `--apply`로 표식).
- **소급 재현 금지**: 지금 만든 청산 규칙을 과거 포지션에 적용하는 것은 라이브 페이퍼가 아니라 백테스트다. 하려면 명시적으로 백테스트로 라벨링해 별도 발행하고 라이브 표본과 섞지 않는다.

## 검증 시계 재시작

주식 트랙의 4주 검증은 **청산 경로가 생긴 시점부터 재시작**한다. 이전 구간은 출구가 없어 승률·실현 R이 원리적으로 산출 불가였으므로 "검증 불능"으로 기록한다. 유실일 처리 규격은 [`docs/PaperObservability.md`](PaperObservability.md), 시계 계산은 `app/worker/liveness.py::elapsed_excluding_gaps()`.

## 커버리지 레인

커버리지 진입분도 **동일한 청산 규칙**을 받는다(`_process_exits`는 `entry_mode`를 구분하지 않고 보유 포지션 전체를 순회한다). 청산 없는 커버리지 레인은 표본을 만들지 못하므로 존재 의미가 없기 때문이다. 성과 집계 분리는 기존대로 `entry_mode` 태그로 유지한다.
