## 1. 정석 (Standard)

### 1-1. 세 법칙

| 법칙 | 내용 | 구현 상태 |
|---|---|---|
| 수급 (Supply & Demand) | 가격은 수요·공급 불균형의 결과 | 부분 구현 |
| 원인과 결과 (Cause & Effect) | 레인지에 축적된 "원인"의 크기가 이후 이동의 "결과"를 결정. PnF 수평 카운트로 계량 | **연결 안 됨** (D12) |
| 노력 대 결과 (Effort vs Result) | 거래량(노력)과 가격 진전(결과)의 괴리가 전환 신호 | **미구현** (D11) |

### 1-2. 스키매틱 — 맥락이 국면을 가른다

축적은 마크다운(하락) 뒤에, 분산은 마크업(상승) 뒤에 형성된다. **같은 모양의 박스라도 앞의
추세가 무엇이었느냐가 축적/분산을 결정한다.** 박스 내부 모양만으로는 결정되지 않는다.

### 1-3. Phase A~E 와 이벤트

**축적 (하락 뒤)**

| Phase | 기능 | 이벤트 |
|---|---|---|
| A | 하락 추세 정지 | PS → SC → AR → ST |
| B | **원인 축적** — 시간이 걸린다 | 반복 ST, 레인지 내 흡수 |
| C | 최종 흔들기 | Spring → Test |
| D | 수요 우위 확인 | SOS → LPS |
| E | 마크업 | 레인지 이탈 상승 |

**분산 (상승 뒤)**: BC → AR → ST / UT·UTAD → SOW → LPSY → 마크다운. 축적의 거울상.

Phase B는 제2법칙(원인과 결과)에서 말하는 "새 추세를 위한 원인을 쌓는" 기능을 한다.

### 1-4. 거래 범위(TR)의 정의

축적 스키매틱의 TR은 **매도 클라이맥스의 저점과 자동 반등의 고점 사이**로 정의된다.
TR이 먼저 있고 그 안에서 이벤트를 찾는 게 아니라, **이벤트가 TR을 정의한다.** 인과 방향이 중요하다.

### 1-5. 진입 지점은 두 곳뿐

Spring과 LPS가 두 주요 진입 지점이다. Spring은 가장 낮은 가격을 주지만 지지선 아래에서
매수하므로 위험이 크고, LPS는 SOS 이후의 눌림으로 약간 높은 가격에서 더 나은 손익비를 준다.

즉 **"국면이 축적이다"는 방향 판단이고, 진입은 그 안의 특정 지점에서만 한다.** 다른 층위다.

### 1-6. 거래량 비대칭

축적에서는 레인지 내 상승 구간 거래량이 하락 구간보다 강하고, 분산에서는 하락 구간이 무겁다.
그리고 **Spring은 저거래량으로 확인될 때 주요 매수 신호가 된다** — 저볼륨이 좋은 신호인
이벤트가 존재한다는 점이 핵심이다.

### 1-7. 예외 — 재축적 / 재분산

장기 상승 추세 중 재축적 TR에서는 PS·SC·ST가 Phase A에 뚜렷하지 않고, 오히려 Phase A가
**분산에서 보이는 형태를 닮는다.** 재축적 TR의 Phase B~E는 원래 축적 바닥보다 짧고 진폭이 작다.

> **D1을 "하락 뒤=축적"이라는 단순 규칙으로 고치면 이 케이스를 전부 잘못 잡는다.**
> 수리 설계 시 필수 고려 사항이다.

### D1 — 선행 추세가 국면 판정에 안 들어간다

```python
engine.py:75   trend = _trend_payload(ordered, {...})   # 계산은 한다
engine.py:97   phase = _phase_from_events(events)        # events 만 받는다
```

`_phase_from_events(events)`는 추세를 **인자로 받지도 않는다.** 축적/분산 이벤트의 최대
신뢰도를 비교해 8점 이상 벌어지는 쪽으로 정한다(`engine.py:526-529`). `trend`는 결과 dict에
붙기만 한다.

### D2 — TR이 이벤트로 정의되지 않는다

`_detect_trading_range`(160)는 일반 S/R 레벨 목록에서 점수 높은 지지·저항 **쌍**을 고른다.
조건은 폭(ATR 1.2~18배, 종가 대비 35% 이하)과 박스 안 캔들 수뿐이다(`engine.py:178-183`).

정석은 반대다 — SC 저점과 AR 고점이 TR을 **정의**한다. 현재는 박스를 먼저 만들고 그 안에서
SC/AR을 찾으므로, **클라이맥스에 앵커되지 않은 임의의 횡보가 전부 TR이 된다.**

### D3 — 이벤트 시퀀스를 요구하지 않는다

`_detect_events`는 캔들마다 각 이벤트 조건을 **독립적으로** 검사한다. 순서 제약이 없다.
`_accumulation_phase`/`_distribution_phase`도 `event_types` **집합 포함 여부**만 본다
(`engine.py:535-560`). SC 없는 Spring, AR 없는 ST, BC 없는 UTAD가 전부 성립한다.
A→B→C→D→E 연쇄가 코드에 존재하지 않는다.

### D4 — Phase C 단일 이벤트로 국면이 성립

```python
engine.py:559   elif "utad_candidate" in event_types:  phase = "distribution_phase_c"
engine.py:540   elif "spring_candidate" in event_types or "test_candidate" in event_types:
                    phase = "accumulation_phase_c"
```

선행 클라이맥스도, Phase B 성숙도도, 레인지 지속 기간도 요구하지 않는다. **스윕 한 번이면
국면이 확정된다.**

### D5 — 거래량 채점 부호가 정석과 반대 ★

`_volume_component`(708)는 거래량이 클수록 점수를 준다:

```
relative >= 2.0  → 25점      relative >= 1.5  → 20점
relative >= 1.15 → 14점      relative >= 0.85 →  8점
그 미만          →  3점
```

그런데 감지 조건은 반대를 요구한다:

```
engine.py:372   test_candidate    volume <= avg_volume * 0.95
engine.py:276   secondary_test    volume <= avg_volume * 1.05
```

**저볼륨을 요구해서 감지해놓고, 그 저볼륨에 3점을 준다.** 정석상 Spring·Test·ST의 저볼륨은
"공급이 소진됐다"는 가장 좋은 증거인데, 현재 채점은 교과서적으로 가장 우수한 Test에
**최저 신뢰도**를 부여한다.

그리고 `_phase_from_events`는 **최대 신뢰도**로 국면을 정하므로(`engine.py:518-521`),
이 왜곡이 그대로 국면 판정에 전달된다.

> **감지 조건과 채점 함수가 서로 반대 방향을 본다. 단일 결함으로는 이게 가장 크다.**

### D6 — `return_speed`가 상수다

`_return_speed_component`(697)는 `bars_to_return`으로 점수를 낸다. 그런데 그 값은 14개
`_event()` 호출부에 **전부 리터럴로 하드코딩**돼 있다(`engine.py:225,241,257,273,289,305,
321,337,353,369,385,429,448,473`).

| 이벤트 | bars_to_return | 점수 |
|---|---|---|
| Spring · UTAD · SOS · SOW | 0 | 25 |
| AR · ST | 2~3 | 14 |
| SC · BC | 4 | 8 |

실제 복귀 속도를 재지 않는다. 빠르게 되돌린 스프링과 느리게 되돌린 스프링이 같은 25점을
받는다. **측정처럼 보이는 타입별 고정 가산점**이다.

### D7 — Spring·UTAD에만 거래량 조건이 없다

```
SC/BC        volume >= avg * 1.6      (engine.py:675,679)
SOS/SOW/AR   volume >= avg * 1.1      (engine.py:244,340,356)
ST           volume <= avg * 1.05     (engine.py:276,292)
Test         volume <= avg * 0.95     (engine.py:372)
Spring       조건 없음                (engine.py:308)

```

**Phase C를 확정하는 두 이벤트만 순수 가격 조건이다.** 거래량 없는 이탈과 동반 이탈이
구분되지 않는다.

### D8 — 이벤트 12개 절단이 Phase A를 먼저 버린다

```python
engine.py:392   return sorted(events, key=lambda event: (event["time"], event["type"]))[-12:]
```

가장 **최신** 12개만 남긴다. SC·AR·PS는 레인지에서 가장 오래된 이벤트라 먼저 잘린다.
phase_a 분기는 `{selling_climax, automatic_rally, secondary_test}` 존재를 요구하므로
(`engine.py:545`), 절단이 국면 라벨을 바꿀 수 있다. **국면의 정체성을 정하는 근거가 먼저
사라지는 구조다.**

### D9 — 라벨 맥락화가 한 방향으로만 작동

`_contextualize_event_labels`(127)의 주석은 정확하다 — "매집 우세로 판정된 레인지에서 상단
스윕은 UT이므로 재명명한다". 그런데 코드는:

```python
engine.py:136   if side != "accumulation":
                    return events
```

**축적 판정일 때만** 작동한다. 분산으로 오판되면 라벨이 오판을 따라가 UTAD로 표시된다.
화면상 완벽하게 정합적으로 보이므로 **오판이 스스로를 은폐한다.**

### D10 — 국면과 이벤트의 이중 계상

`_wyckoff_evidence`(269)는 국면 증거 1건 + 마커별 증거 N건을 **모두** 낸다. 중복 억제는
국면을 명시적으로 제외한다:

```python
confluence.py:900   if engine == "wyckoff":
                        if "국면" in claim:
                            return None   # "국면 증거는 이벤트가 아니다"
```

분류상으로는 맞지만 **인과상으로는 틀렸다.** 국면은 `_phase_from_events`에서 이벤트 최대
신뢰도의 함수로 결정된다. 같은 UTAD가 마커로 한 표, 그 마커가 만든 국면으로 또 한 표를 던진다.

### D11 — Effort vs Result 미구현

세 법칙 중 하나가 코드에 없다. 거래량(노력) 대비 가격 스프레드·진전(결과)의 괴리를 재는
함수가 없다. `_volume_component`는 거래량 **절대량**만 본다. "대량 거래에도 진전이 없다"가
와이코프의 핵심 전환 신호인데 감지할 수 없다.

### D12 — Cause & Effect가 국면에 연결 안 됨

PnF 수평 카운트는 `WO-FCE-PNF-TARGET-01`로 구현돼 있으나 그 WO의 C2 경계상 **목표가 계산
전용**이다. TR이 축적한 "원인의 크기"가 국면 신뢰도나 진입 판단에 들어가지 않는다.
정석에서 원인의 크기는 결과의 크기를 예측하는 것이지 목표선만 그리는 게 아니다.

### D13 — 진입 지점 개념이 없다 ★

`evaluate_entry`(`paper/policy.py:110`) 게이트 9종에 와이코프 항목이 **0개**다
(`grep -i wyckoff paper/policy.py` → 결과 없음). 국면은 `stance`를 통해 가중치 18짜리
투표 하나로만 반영된다.

정석에서 진입은 **Spring과 LPS 두 지점뿐**이다. 현재 엔진은 "지금 축적이다"까지만 알고
"레인지 안 어디서 들어가는가"는 규정하지 않는다.

> **엔진은 와이코프로 매매하지 않는다. 와이코프를 여러 투표자 중 하나로 쓴다.**

### D14 — MTF 정렬 스텁

`engine.py:119`가 `{"htf_phase": None, "htf_trend": None, "alignment": "neutral"}`로
초기화하고 `include_mtf=True`일 때만 :122에서 덮어쓴다. `include_mtf=False` 경로(HTF 재귀
호출 자신)는 상위 맥락 없이 나간다.

### D15 — 재축적/재분산 미구분

정석상 재축적 TR의 Phase A는 분산과 닮는다(§1-7). 현재 구현에 구분이 없고, **D1을 단순
규칙으로 수리하면 이 케이스를 체계적으로 오판한다. D1 수리 설계의 선결 조건이다.**

## 4. 우선순위 제안 (적용 아님)

동시 투입 금지(C3) 전제. 하나씩 적용하고 전후를 실측 대조해야 한다.

| 순위 | 항목 | 이유 | 방향성 |
|---|---|---|---|
| 1 | **D5** 거래량 채점 부호 | 감지와 채점이 모순. 다른 모든 신뢰도가 이 위에 얹혀 있다 | 신뢰도 재분포 — 양방향 |
| 2 | **D1+D15** 선행 추세 게이트 | 방향 오판의 직접 원인. 재축적 예외 동반 필수 | **보수화만** (불일치 → `undetermined`) |
| 3 | **D8** 절단 정책 | 저비용. Phase A 보존만 하면 됨 | 관측 복원 |
| 4 | **D9** 라벨 맥락화 대칭화 | 저비용. 오판 은폐 제거 | 표시만 |
| 5 | **D4+D3** 시퀀스·성숙도 요건 | 국면 성립 조건 강화 | 진입 감소 |
| 6 | **D10** 이중 계상 | 가중치 체계 변경이라 파급 큼 | 신뢰도 하향 |
| 7 | **D13** 진입 지점 도입 | 설계 신설. 가장 크고 가장 나중 | 진입 규칙 재정의 |
| — | D2·D11·D12·D14 | 재설계급. 위가 정리된 뒤 판단 | — |

**2번은 반드시 보수화 방향으로만 설계한다.** 추세 불일치 시 국면을 `undetermined`로 내리는
것은 진입을 없애기만 하고 만들지 않으므로 비대칭 자율 원칙에 맞고 즉시 적용 가능하다.
같은 상황에서 반대편(축적/롱)을 **내는** 것은 진입을 만드는 방향이라 candidate 등록 +
거부권 창을 거쳐야 한다. **두 개는 다른 WO다.**

## 5. 사용자 결정 필요

1. **D5를 정합 수리로 볼 것인가, 개선안으로 볼 것인가.** 감지 조건과 채점이 모순이므로 정합
   수리 주장이 가능하지만, 신뢰도가 재분포되면 진입 건수가 양방향으로 변한다.
   `confirmed_flip` → `stable_direction` 선례와 같은 범주로 처리할지.
2. **와이코프를 투표자로 둘 것인가, 진입 규칙으로 승격할 것인가** (D13). 전자면 지금 구조가
   맞고 결함은 신뢰도 정확도 문제다. 후자면 `evaluate_entry`에 와이코프 게이트를 신설하는
   설계 변경이다. **이 결정이 나머지 전부의 전제다.**
3. **신규 감지기 모라토리엄 저촉 여부.** AGENTS.md상 validated 승격 1호 전까지 신규 감지기
   금지다. D11(Effort vs Result)은 신규 감지기에 해당할 소지가 있다. D1·D5·D8·D9는 기존
   감지기의 정합 수리라 저촉되지 않는다고 본다.

## 6. ICT — 미착수

ICT(Inner Circle Trader) 적용은 별도 리서치 대상이다. 착수 전 확인:

- 와이코프와 **개념 중첩**이 크다(liquidity sweep ↔ Spring/UTAD, order block ↔ LPS/LPSY).
  두 엔진을 나란히 배선하면 `_suppress_overlaps`가 동근원 이중 가점을 못 막을 가능성 —
  **D10과 같은 종류의 문제가 반복된다.**
- 기존 `structure/liquidity` 모듈이 이미 스윕을 다룬다. 중복 구현 검사(불변 규칙 2) 선행.
- 신규 감지기 모라토리엄 적용 대상.

**와이코프 정합화가 끝나기 전에 ICT를 얹으면 무엇이 효과였는지 영원히 알 수 없다.**
